## Information Security Overview

| Fact | Sources | verify |
|---|---|---|
| CIA: confidentiality (no unauthorized disclosure), integrity (no unauthorized change or destruction, includes authenticity and non-repudiation), availability (timely, reliable access). | NIST CSRC glossary (confidentiality, integrity, availability); NIST SP 800-12 Rev. 1 | no |
| Authenticity = the property of being genuine and verifiable; non-repudiation = the sender cannot deny sending (digital signatures). | NIST glossary "authenticity", "non-repudiation" and "digital signature" | no |
| Information assurance = measures that protect information and systems by ensuring availability, integrity, authentication, confidentiality and non-repudiation, including restoration (protect, detect, react). | NIST glossary "information assurance" (CNSSI 4009); NIST SP 800-12 Rev. 1 | no |
| Passive attack: monitors or captures data without changing it (eavesdropping, traffic analysis). Active attack: changes data or system state (modification, DoS, spoofing). | NIST glossary "passive attack" and "active attack"; MITRE ATT&CK T1040 (network sniffing) vs T1498 (network DoS) | no |
| Supply-chain (EC-Council: "distribution") attack: tampering with hardware or software before it reaches the victim. | NIST glossary "supply chain attack"; MITRE ATT&CK T1195 | no (the label "distribution" is EC-Council's: tag `ec-council-specific`) |
| Insider threat: a trusted person misuses authorized access, knowingly or not. | NIST glossary "insider threat"; CISA "Insider Threat Mitigation" | no |
| Close-in attack: the attacker is physically near the target (shoulder surfing, dumpster diving, eavesdropping in person). Five-class list passive / active / close-in / insider / distribution comes from the NSA Information Assurance Technical Framework. | EC-Council course page (topic "Classification of Attacks"); IATF (no stable public URL found) | **yes** |
| Attack = motive (goal) + method + vulnerability. | EC-Council framing only | **yes** |
| Zero-day attack: exploits a vulnerability unknown to the vendor/defenders. | NIST glossary "zero day attack"; CVE program overview | no |

## Hacking Concepts and Hacker Classes

| Fact | Sources | verify |
|---|---|---|
| NIST/CNSSI define "hacker" as an unauthorized user who attempts to gain or gains access; ethical hacking uses the same skills with permission. | NIST glossary "hacker"; NIST SP 800-115 | no |
| Classes as the exam names them: white, black, gray hats; script kiddies; hacktivists; state-sponsored; cyber terrorists; insiders; suicide hackers; organized crime. | EC-Council course page ("Hacker Classes", names only); ref-04 | **yes** |
| APT: a well-resourced adversary that uses several vectors and stays in the network for a long time to reach its goals, often state-linked. | NIST glossary "advanced persistent threat"; CISA "Advanced Persistent Threats and Nation-State Actors" | no |

| Threat actor = an individual or group posing a threat. | NIST glossary "threat actor" (SP 800-150); NIST IR 8286 | no |

## Ethical Hacking Concepts

| Fact | Sources | verify |
|---|---|---|
| Rules of engagement (ROE): detailed guidelines and constraints for security testing, set before the test starts; they give the testers authority for the defined activities. | NIST glossary "rules of engagement" (SP 800-115); NCSC "Penetration testing" (scope) | no |
| Testing without written permission is a crime (US CFAA, UK Computer Misuse Act). | 18 U.S.C. §1030 (Cornell LII); Computer Misuse Act 1990 (legislation.gov.uk) | no |
| NIST SP 800-115 penetration testing phases: planning, discovery, attack, reporting. | NIST SP 800-115 §5.2 (landing page and PDF). The fact is what this document says, so the document itself is the authority. | no |
| PTES has 7 sections: pre-engagement interactions, intelligence gathering, threat modeling, vulnerability analysis, exploitation, post exploitation, reporting. | pentest-standard.org main page; OWASP WSTG introduction (framework comparison) | no |
| Black box = no prior knowledge; white box = full knowledge; gray box = partial. | OWASP WSTG introduction; NIST SP 800-115 (testing viewpoints) | no |
| Vulnerability assessment = systematic examination to find deficiencies (no exploitation); penetration test = tries to exploit them; red team = emulates an adversary against the defenders (blue team). | NIST glossary "vulnerability assessment", "red team", "blue team"; NCSC "Penetration testing" | no |
| Announced vs unannounced (overt vs covert) tests: covert tests also measure the staff's detection and response. | NIST SP 800-115 §2.4 (overt and covert testing); NCSC | no |
| Bug bounty = paying individuals for reporting security bugs; a vulnerability disclosure policy tells researchers what they may test and how to report. | NIST glossary "bug bounty" (SP 800-216); CISA BOD 20-01; ISO/IEC 29147 | no |
| US DOJ (May 2022): good-faith security research should not be charged under the CFAA. | DOJ press release 2022-05-19; 18 U.S.C. §1030 | no |
| AI-driven ethical hacking: AI helps with recon summaries, code and log analysis and report writing; outputs must be checked (hallucinations), client data must not leak into public AI services, and LLM apps are new targets (prompt injection). Example tools: ShellGPT, PentestGPT. | EC-Council course page (topics "AI-Driven Ethical Hacking", "ChatGPT-Powered AI Tools"); OWASP Top 10 for LLM Applications; NIST AI RMF; tool GitHub repos | **yes** (EC-Council tool list may differ) |

## Hacking Methodologies and Frameworks

| Fact | Sources | verify |
|---|---|---|
| Five phases (EC-Council): reconnaissance, scanning, gaining access, maintaining access, clearing tracks. | EC-Council course page; widely repeated in public study guides | **yes** |
| CEH ethical hacking framework: footprinting and reconnaissance → scanning → enumeration → vulnerability analysis → system hacking (gaining access, escalating privileges, maintaining access, clearing logs). | EC-Council course page (topic "CEH Ethical Hacking Framework", module order) | **yes** |
| Cyber Kill Chain, 7 stages: reconnaissance, weaponization, delivery, exploitation, installation, command and control, actions on objectives. | Lockheed Martin Cyber Kill Chain page; Hutchins, Cloppert, Amin white paper (2011) | no |
| Courses of action per kill chain stage: detect, deny, disrupt, degrade, deceive, destroy. | Lockheed Martin white paper (course-of-action matrix); Lockheed Martin kill chain page | no |
| ATT&CK Enterprise has 14 tactics, from Reconnaissance to Impact. Tactic = why, technique = how, procedure = a specific implementation. | attack.mitre.org tactics list; MITRE ATT&CK resources ("Design and Philosophy") | no |
| Clearing tracks maps to ATT&CK T1070 Indicator Removal; clearing Windows logs (T1070.001) creates Security event 1102 "The audit log was cleared". | MITRE ATT&CK T1070 and T1070.001; Microsoft Learn event 1102 and `wevtutil` | no |
| Diamond Model: adversary, capability, infrastructure, victim; analysts pivot between features. | Caltagirone, Pendergast, Betz (2013) PDF; DTIC ADA586960 | no |
| Indicator = technical artifact or observable that suggests an attack is imminent, underway, or has happened (IoC). TTPs describe behavior. | NIST glossary "indicator" and "TTPs" (SP 800-150); NIST SP 800-150 | no |
| Threat intelligence = threat information that is aggregated, analyzed and enriched to support decisions. | NIST glossary "threat intelligence"; NIST SP 800-150 | no |
| Threat intelligence lifecycle: planning and direction, collection, processing, analysis and production, dissemination (plus feedback). Four types: strategic, operational, tactical, technical. | US Joint Publication 2-0 (intelligence cycle); EC-Council course page (topic name) | **yes** |

## Information Security Controls

| Fact | Sources | verify |
|---|---|---|
| Control types by implementation (administrative/management, technical, physical) and by function (preventive, detective, corrective, deterrent, recovery, compensating). Compensating = alternative control giving comparable protection. | NIST glossary "security control" and "compensating security control"; NIST SP 800-53 Rev. 5 | no |
| Defense in depth = layered, independent controls; least privilege. | NIST glossary "defense-in-depth" and "least privilege"; CISA defense-in-depth recommended practice | no |
| Risk is a function of likelihood and impact of a threat exploiting a vulnerability. Responses: accept, avoid, mitigate, share/transfer. | NIST SP 800-30 Rev. 1; NIST SP 800-39 | no |
| NIST risk management process: frame, assess, respond, monitor. | NIST SP 800-39 §2; NIST glossary "risk management" | no |
| Incident response lifecycle (SP 800-61 Rev. 2): preparation; detection and analysis; containment, eradication and recovery; post-incident activity. Rev. 3 (2025) maps incident response onto the CSF 2.0 functions. | NIST SP 800-61 Rev. 2 and Rev. 3 pages | no |
| NIST CSF 2.0 has six functions: Govern, Identify, Protect, Detect, Respond, Recover (Govern new in 2.0). | NIST CSWP 29 (CSF 2.0); nist.gov/cyberframework | no |
| Zero trust: no implicit trust based on network location; every access request is authenticated and authorized. | NIST SP 800-207; NIST glossary "zero trust" | no |
| Threat modeling: identify what can go wrong and what to do about it, early in design. | OWASP Threat Modeling page; NIST glossary "threat modeling" | no |
| CIS Controls v8: 18 prioritized safeguard groups. | cisecurity.org Controls v8; NCSC 10 Steps (for a comparable framework) | no |
