## Footprinting Concepts

| Fact | Sources | verify |
|---|---|---|
| Footprinting (reconnaissance) collects information about a target before an attack. Passive: no direct interaction (search engines, public records, archives). Active: direct interaction (querying the target's DNS, probing, calling staff). | MITRE ATT&CK Reconnaissance tactic TA0043 (T1593/T1596 vs T1595); NIST SP 800-115 §4 (review and discovery) | no |
| Objectives: organization info (people, roles, locations, partners), network info (domains, IP ranges, DNS, hosts), system info (OS, services, technologies). | ATT&CK T1591, T1590, T1592; OWASP WSTG Information Gathering overview | no |
| OSINT = intelligence built from publicly available sources. | ATT&CK T1593 and T1596 (open websites, open technical databases); OSINT Framework | no |
| Footprinting is phase 1 of the hacking phases and the first step of the CEH framework. | EC-Council course page (module order); ref-04 | **yes** |

## Footprinting through Search Engines

| Fact | Sources | verify |
|---|---|---|
| Google operators: `site:`, `filetype:`, `intitle:`, `inurl:`, `intext:`, exact phrase `"…"`, exclusion `-`. `site:` limits results to a domain or URL prefix; `filetype:` to a file type. | Google Search Central "site: search operator"; Google Search Help "Refine web searches" | no |
| Google hacking ("dorking") combines operators to find exposed documents, login pages, directory listings and error messages. The Google Hacking Database (GHDB, Exploit-DB) catalogs such queries. | Exploit-DB GHDB; OWASP WSTG-INFO-01 (search engine reconnaissance) | no |
| Google's `cache:` operator was retired in 2024; archived copies now come from the Internet Archive's Wayback Machine. | Google Search Central operator list (no `cache:`); web.archive.org | **yes** |
| Search engine reconnaissance is passive for the target (the search engine's crawler did the contact). | OWASP WSTG-INFO-01; ATT&CK T1593.002 (search engines) | no |

## Whois Footprinting

| Fact | Sources | verify |
|---|---|---|
| WHOIS is a query/response protocol on TCP port 43. It returns registrar, registration and expiry dates, name servers and, where not redacted, contacts. | RFC 3912; ICANN Lookup; Kali `whois` | no |
| RDAP (RFC 7480 family; RFC 9082 queries, RFC 9083 JSON responses) is the HTTPS/JSON successor. Since 28 January 2025 gTLD registries and registrars are no longer required to run WHOIS (except .com, .name, .post). | ICANN RDAP page; RFC 9082/9083 | no |
| Since the GDPR (2018), most personal contact data in gTLD registration records is redacted. | ICANN gTLD registration data specifications; ICANN RDAP page | no |
| IP address ownership is looked up in the five Regional Internet Registries: ARIN, RIPE NCC, APNIC, LACNIC, AFRINIC. | NRO "RIRs"; ARIN Whois; RIPE Database | no |
| Thick WHOIS registries store full contact data; thin registries store only domain and registrar data and point to the registrar. | ICANN registration data specs; RFC 3912 (protocol only) | **yes** |

## DNS Footprinting

| Fact | Sources | verify |
|---|---|---|
| Record types: A, AAAA, MX, NS, CNAME, SOA, PTR, TXT (SPF, DMARC, verification tokens), SRV (services), HINFO (host info). | RFC 1035; RFC 2782 (SRV); Cloudflare "DNS records" | no |
| A zone transfer (AXFR) copies a whole zone over TCP 53. Servers must restrict it to secondary servers, ideally with TSIG. | RFC 5936; RFC 8945 (TSIG); BIND `allow-transfer` | no |
| `nslookup` (Windows/Linux), `dig` and `host` query DNS; `dig axfr @ns zone` requests a transfer. DNSRecon and dnsenum automate record lookups, brute-force of subdomains and transfer attempts. | BIND manpages (dig, host); Microsoft `nslookup`; Kali dnsrecon and dnsenum pages | no |
| Reverse DNS (PTR in in-addr.arpa) maps IP addresses back to names. | RFC 1035 §3.5; Cloudflare DNS records | no |
| DNSSEC NSEC records allow "zone walking" (listing names); NSEC3 hashes names to make it harder. | RFC 4034 §4; RFC 5155 | no |
| Many servers answer `ANY` queries minimally, so `ANY` is no longer a reliable way to dump records. | RFC 8482; BIND reference | no |

## Network and Email Footprinting

| Fact | Sources | verify |
|---|---|---|
| Traceroute sends probes with increasing TTL; each router that drops a probe returns ICMP Time Exceeded, revealing the path. Windows `tracert` uses ICMP Echo; Linux `traceroute` uses UDP (ports from 33434) by default, with `-I` for ICMP and `-T` for TCP SYN. | Microsoft `tracert`; man7 traceroute(8); RFC 792 | no |
| Network range: find the organization's IP blocks and ASN in RIR databases. | ARIN Whois; RIPE Database; ATT&CK T1590.005 (IP addresses) | no |
| E-mail headers: `Received:` lines are added by each relay, newest on top, so the path is read bottom-up; `Return-Path`, `Message-ID`, and `Authentication-Results` (SPF, DKIM, DMARC) help trace and judge a message. | RFC 5321 §4.4; RFC 5322 §3.6; RFC 8601; Google "Trace an email with its full headers" | no |
| SPF (RFC 7208) lists allowed sending servers; DKIM (RFC 6376) signs messages; DMARC (RFC 7489) sets policy and reporting. Their TXT records also reveal the mail providers an organization uses. | RFCs 7208, 6376, 7489; Cloudflare "DMARC, DKIM and SPF" | no |
| E-mail tracking tools use a hidden image or link to learn when and where a message is opened (IP, client). | ATT&CK T1598 (phishing for information); CISA phishing guidance | **yes** |

## Footprinting Countermeasures

| Fact | Sources | verify |
|---|---|---|
| robots.txt is not access control: listing paths makes them public. | RFC 9309 §2.2; OWASP WSTG-INFO-03 | no |
| Reduce exposure: remove metadata, limit public details (org charts, technologies in job ads), use registrar privacy, restrict zone transfers, split-horizon DNS, generic error pages, disable directory listing. | ATT&CK M1056; OWASP WSTG-INFO-01 to -05; RFC 5936 | no |
| Monitor your own exposure: search your domains in Shodan/Censys, CT logs and breach services; run regular OSINT on yourself. | Shodan help; RFC 9162; HIBP | no |
| Staff awareness and social media policy. | NCSC social media guidance; CISA phishing guidance | no |
