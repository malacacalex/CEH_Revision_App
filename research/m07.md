# Research: M7 Malware Threats

Scope: the five sections in `content/modules/m07/meta.json`. The public CEH v13 course page lists the module's
key topics (malware, APT lifecycle, Trojan, virus, ransomware, computer worms, fileless malware, AI-based
malware, malware analysis, static and dynamic malware analysis, virus detection methods, malware
countermeasures, anti-Trojan software, AI-powered malware detection and analysis tools) and three labs
(control a victim with a Trojan, infect a system with a virus, static and dynamic analysis). That list is used
for scope only; all wording below is ours, from public primary sources.

The module is written at exam-knowledge level and from the defender's side: what each malware type is and
does, how to recognize it, how analysts study it, and how to prevent, detect and clean it up. There is no
malware code, builder usage or evasion recipe anywhere in the content.

Every fact was checked against at least two independent sources. **verify** marks EC-Council-specific lists
and terms (tag `ec-council-specific`) and facts backed by a single source.

Checked on 2026-09-23. URLs tested with curl and a browser User-Agent: all 200, except the NSA deepfake PDF,
SourceForge (Regshot, rkhunter) and OpenAI (403 from bot protection) and TryHackMe rooms (429). Removed
(404): NIST glossary slugs ransomware, keystroke_logger, adware, bot, zombie, dropper, exploit_kit,
boot_sector_virus, multipartite_virus, polymorphic_virus, stealth_virus, file_infector_virus, sandboxing,
heuristic, deepfake, reverse_engineering, integrity_checking, sheep_dip; Microsoft "ransomware-malware" and
"malware-naming"; VirusTotal "code-insight" and "results-reported"; CISA "recovering from viruses"; SANS
cheat-sheet poster.

## Malware and APT Concepts

| Fact | Sources | verify |
|---|---|---|
| Malware = software or firmware intended to perform an unauthorized process that harms confidentiality, integrity or availability. | NIST glossary "malware"; NIST SP 800-83 Rev. 1 §2 | no |
| Virus: self-replicates by inserting copies of itself into host programs or data files; usually triggered by user action (running a program, opening a file). | NIST glossary "virus"; SP 800-83 Rev. 1 §2.1; Microsoft "Understanding malware" | no |
| SP 800-83 virus subtypes: compiled (file infector, boot sector, multipartite = file + boot) and interpreted (macro, scripting). | SP 800-83 Rev. 1 §2.1; NIST glossary "macro virus" (SP 800-28) | no |
| Worm: self-replicating, self-contained, runs without user intervention; network service worms exploit a service flaw, mass-mailing worms send themselves by e-mail. | NIST glossary "worm"; SP 800-83 Rev. 1 §2.1; Microsoft "Worms" | no |
| Trojan horse: self-contained, **non-replicating** program that looks benign but has a hidden malicious purpose; often delivers other tools. | NIST glossary "trojan horse"; SP 800-83 §2.1; Microsoft "Trojans" (can't spread on their own) | no |
| Blended attack (SP 800-83 sense) = uses several infection or transmission methods; most modern malware is blended. NIST glossary also has a cyber-physical sense. | SP 800-83 Rev. 1 §2.1; NIST glossary "blended attack" | no |
| Attacker tools (SP 800-83 §2.2): backdoors (listen for commands; bots/zombies and remote administration tools), keystroke loggers, rootkits, malicious browser plug-ins, e-mail generators, toolkits. | SP 800-83 Rev. 1 §2.2; NIST glossary "backdoor", "rootkit" | no |
| Rootkit: hides the attacker's presence and keeps privileged access; kernel/boot-level rootkits are the hardest to detect. | NIST glossary "rootkit"; ATT&CK T1014; Microsoft "Rootkits" | no |
| Bootkit: modifies boot sectors so code runs before the OS loads; defended by Secure Boot and firmware integrity. | ATT&CK T1542.003; Microsoft Secure Boot docs; NIST SP 800-147/193 | no |
| Botnet: many compromised hosts controlled remotely through C2; Mirai used default IoT credentials over Telnet for DDoS. | NIST glossary "botnet"; CISA alert on Mirai (2016) | no |
| Ransomware encrypts data for impact and often deletes shadow copies and backups first; double extortion adds data theft. | ATT&CK T1486 and T1490; CISA #StopRansomware Guide | no |
| WannaCry (2017) spread as a worm over SMBv1 (MS17-010 / EternalBlue). | CISA WannaCry alert; Microsoft MS17-010 bulletin | no |
| Emotet: Trojan spread by phishing attachments/links, with worm-like spread and use as a dropper/loader for other malware. | CISA AA20-280A; ATT&CK S0367 | no |
| Spyware collects information secretly; keyloggers record keystrokes (T1056.001). | NIST glossary "spyware"; ATT&CK T1056.001; SP 800-83 §2.2 | no |
| Logic bomb: code that triggers a malicious function when a condition is met (date, event). | NIST glossary "logic bomb"; NIST glossary "virus" note (date trigger) | no |
| Cryptojacking/coin miners hijack CPU/GPU resources (resource hijacking). | ATT&CK T1496; Microsoft "Coin miners" | no |
| PUA/adware: potentially unwanted apps that show ads or bundle software; not always malware but raise risk. | Microsoft Defender PUA page; SP 800-83 (tracking cookies/adware context) | **yes** (NIST glossary has no adware entry) |
| Malware components as EC-Council names them: crypter, downloader, dropper, exploit, injector, obfuscator, packer, payload, malicious code; wrappers/binders join a Trojan to a legitimate program. | EC-Council course page (topic names); ATT&CK T1027 / T1027.002 (packing, obfuscation); CISA AA20-280A (dropper) | **yes** (`ec-council-specific`) |
| Polymorphic malware changes its code or encryption on each infection while the function stays the same; metamorphic rewrites its whole body. Both defeat simple signatures. | ATT&CK T1027 (obfuscation); Google GTIG AI report (self-rewriting PROMPTFLUX); EC-Council virus types | **yes** |
| EC-Council virus types include stealth, polymorphic, metamorphic, encryption, cavity, sparse infector, companion, shell, file-extension, macro, boot sector, multipartite. | EC-Council course page (topic "Virus"); SP 800-83 (for the NIST subset) | **yes** (`ec-council-specific`) |
| APT: sophisticated, well-resourced adversary that establishes and extends a long-term presence to exfiltrate data or disrupt. | NIST glossary "advanced persistent threat"; CISA APT page; SP 800-83 §2.3 | no |
| APT lifecycle (EC-Council): preparation → initial intrusion → expansion → persistence → search and exfiltration → cleanup. | EC-Council course page (topic "Advanced Persistent Threat Lifecycle") | **yes** (`ec-council-specific`) |
| Common infection vectors: phishing attachments (T1566.001), user execution of a malicious file (T1204.002), drive-by downloads (T1189), removable media (T1091), supply chain (T1195.002), exploitation of remote services (T1210). | MITRE ATT&CK technique pages; SP 800-83 §2.1 (drive-by) | no |
| C2 over common application protocols (T1071); DGAs make blocking domains hard (T1568.002). | ATT&CK T1071, T1568.002; ATT&CK TA0011 | no |
| RATs vs legitimate remote access tools: attackers also abuse legitimate RMM/remote tools (T1219). | ATT&CK T1219; SP 800-83 §2.2 (remote administration tools) | no |

## Fileless Malware Concepts

| Fact | Sources | verify |
|---|---|---|
| Fileless threats run mostly in memory and abuse built-in tools; Microsoft classes them Type I (no file activity, e.g. network exploit), Type II (indirect file activity, e.g. WMI repository, registry) and Type III (files required to operate, e.g. registry verb + mshta). | Microsoft "Fileless threats"; ATT&CK T1027.011 (fileless storage) | no |
| Fileless storage: registry, event logs, WMI repository; Linux shared memory (/dev/shm). | ATT&CK T1027.011; Microsoft "Fileless threats" | no |
| Living off the land (LOTL): abuse of native binaries and admin tools (PowerShell, WMI, certutil, mshta, rundll32, regsvr32). LOLBAS/GTFOBins catalog them. | CISA/partners "Identifying and Mitigating LOTL Techniques"; LOLBAS project; ATT&CK T1218 | no |
| PowerShell (T1059.001) and WMI (T1047) are the classic fileless execution engines; WMI event subscriptions give persistence (T1546.003). | ATT&CK T1059.001, T1047, T1546.003 | no |
| Reflective code loading (T1620) and process injection/hollowing (T1055, T1055.012) run payloads in memory without a backing file. | ATT&CK T1620, T1055.012; Sysmon Event ID 8 (CreateRemoteThread) | no |
| Registry run keys (T1547.001) and scheduled tasks (T1053.005) are common persistence points, including for script-only payloads. | ATT&CK T1547.001, T1053.005; Sysinternals Autoruns | no |
| Fileless infection chain (EC-Council framing): delivery (phishing/exploit) → script or macro starts a native tool → payload loaded in memory → persistence in registry/WMI/tasks. | Microsoft "Fileless threats"; CISA LOTL guide | **yes** |
| Defenses: AMSI lets AV inspect script content after de-obfuscation; PowerShell script block logging writes event 4104; Constrained Language Mode with App Control/AppLocker; ASR rules (Office child processes); EDR memory/behavior telemetry. | Microsoft AMSI docs; about_Logging_Windows; about_Language_Modes; ASR rules reference; Defender EDR overview | no |
| Memory analysis (e.g. Volatility) finds in-memory artifacts that disk scans miss. | Volatility 3 docs; SP 800-86 (volatile data) | no |

## AI-based Malware Concepts

| Fact | Sources | verify |
|---|---|---|
| ATT&CK T1588.007: adversaries obtain generative AI tools to aid recon, scripting, social engineering and even payload development. | ATT&CK T1588.007; Microsoft/OpenAI "Staying ahead of threat actors in the age of AI" (2024) | no |
| Observed use so far is mainly productivity (research, troubleshooting code, content and phishing text), not novel capabilities. | Google GTIG "Adversarial misuse of generative AI" (Jan 2025); Microsoft/OpenAI (2024); NCSC "Impact of AI on the cyber threat" | no |
| NCSC: AI gives the largest uplift in reconnaissance and social engineering; advanced AI malware needs data, expertise and resources. | NCSC assessment; Google GTIG | no |
| Malware that queries an LLM at run time: PROMPTFLUX (VBScript dropper asking Gemini to rewrite its own code, "just-in-time" self-modification) and PROMPTSTEAL (LLM-generated commands). | Google GTIG "AI threat tracker" (Nov 2025); ATT&CK T1027 (obfuscation goal) | **yes** (single vendor for the families) |
| PromptLock (ESET, Aug 2025): first known AI-powered ransomware, a proof of concept that uses a local LLM to generate Lua scripts on the fly; later tied to an academic prototype. | ESET WeLiveSecurity; Google GTIG (same trend) | **yes** |
| Agentic AI misuse: a low-skill actor used an AI coding agent to develop and sell ransomware ("vibe hacking" report). | Anthropic threat intelligence report (Aug 2025); NCSC (lower barrier to entry) | **yes** |
| AI-generated polymorphism defeats hash/signature matching; defenders rely on behavior, memory and network telemetry. | Google GTIG; SP 800-83 §2.3 (customization beats signatures) | no |
| Deepfakes and AI phishing raise social-engineering success (voice/video impersonation). | NSA/FBI/CISA "Contextualizing Deepfake Threats" (2023); NCSC | no |
| Adversarial ML: evasion attacks craft inputs that ML classifiers mislabel; poisoning corrupts training data. ML-based malware detectors are targets too. | NIST AI 100-2 E2025; MITRE ATLAS | no |
| AI-powered detection and analysis: ML models in AV cloud protection; LLM explanation of suspicious scripts (VirusTotal Code Insight); AI assistants in SOC tools. Human verification still needed. | Microsoft Defender cloud protection (ML models); VirusTotal Code Insight blog (2023); EC-Council topic "AI-Powered Malware Detection and Analysis Tools" | **yes** (tool list is EC-Council's) |

## Malware Analysis

| Fact | Sources | verify |
|---|---|---|
| Analysis is done actively (execute in an isolated test system, often a VM that is reverted afterwards) or forensically (examine the infected host from a trusted toolkit); some malware detects VMs. | SP 800-83 Rev. 1 §4.2.4 and footnote 17; ATT&CK T1497 | no |
| Static analysis = examine without running (hashes, strings, headers, imports, packing, disassembly); dynamic = run in a sandbox and watch processes, files, registry, network. | SP 800-83 §4.2.4; SP 800-86; REMnux docs (static vs dynamic sections) | no |
| Sandbox: restricted, controlled execution environment; can be reset to a known good state. | NIST glossary "sandbox"; SP 800-83 §3.5.2; Windows Sandbox docs (disposable) | no |
| Lab prep: isolated network (host-only), snapshots, simulated internet services (INetSim), analysis distros (REMnux, FLARE-VM). EC-Council also calls a dedicated isolated scanning machine a "sheep dip" computer. | INetSim; REMnux; FLARE-VM; EC-Council for "sheep dip" | **yes** for "sheep dip" (`ec-council-specific`) |
| Hash the sample first (SHA-256; MD5 is broken for collisions but still used as an ID): `certutil -hashfile`, `Get-FileHash`. | certutil docs; Get-FileHash docs; RFC 6151 (MD5); FIPS 180-4 | no |
| Online multi-engine scan: VirusTotal aggregates many AV engines and tools; uploaded files are shared with partners and premium users, so look up by hash first for sensitive files. | VirusTotal "How it works"; Sysinternals Sigcheck (VT hash lookup) | no |
| Fuzzy hashing (ssdeep, CTPH) matches similar but not identical files. | ssdeep project; VirusTotal file similarity search | no |
| Strings extraction (Sysinternals Strings: ASCII and Unicode) shows URLs, IPs, messages. | Sysinternals Strings; REMnux docs | no |
| Packing compresses/encrypts an executable and changes its signature; packer detection with Detect It Easy; UPX is a common packer. High entropy and few imports hint at packing. | ATT&CK T1027.002; Detect It Easy; UPX | no |
| PE format: headers, sections, import table (IAT) reveal what APIs the program uses. | Microsoft PE format spec; Detect It Easy | no |
| Disassembly/decompiling (Ghidra, IDA) and debugging (x64dbg) are the deep static/dynamic steps. | Ghidra (NSA); x64dbg; IDA | no |
| Dynamic monitoring tools: Process Monitor (file, registry, process activity), Process Explorer (handles, DLLs), TCPView (endpoints per process), Autoruns (autostart entries), Sysmon (event log telemetry), Wireshark (traffic), Regshot (before/after registry diff). | Sysinternals pages; Wireshark docs; Regshot project | no |
| Sysmon event IDs: 1 process creation (full command line), 3 network connection, 7 image loaded, 8 CreateRemoteThread, 11 FileCreate, 13 registry value set, 22 DNS query. | Sysmon docs; ATT&CK data sources | no |
| Automated sandboxes: CAPE (open source), ANY.RUN, Hybrid Analysis; VirusTotal in-house sandboxes. | CAPE docs; VirusTotal sandboxes page; vendor sites | no |
| YARA: rules of strings plus a boolean condition to identify and classify malware families; used by VirusTotal Livehunt/Retrohunt and in CISA advisories. | YARA docs; VirusTotal YARA docs; CISA WannaCry alert (YARA rules) | no |
| Indicators: artifacts or observables of an attack or compromise; Pyramid of Pain ranks hashes (trivial to change) up to TTPs (hardest). STIX is the exchange format. | NIST glossary "indicator" (SP 800-150); Bianco "Pyramid of Pain"; OASIS STIX intro | no |
| EC-Council malware analysis steps (static: fingerprinting, local/online scanning, strings, packing/obfuscation, PE info, dependencies, disassembly; dynamic: port, process, registry, services, startup, event log, installation, files, drivers, network, DNS, API monitoring). | EC-Council course page (topic names); REMnux/Sysinternals for tool mapping | **yes** (`ec-council-specific`) |
| Memory forensics with Volatility 3. | Volatility 3 docs; SP 800-86 | no |

## Malware Countermeasures

| Fact | Sources | verify |
|---|---|---|
| Prevention elements: policy, awareness, vulnerability mitigation (patching), threat mitigation (AV, IPS, firewalls, content filtering, allowlisting), defensive architecture (sandboxing, browser separation, virtualization). | SP 800-83 Rev. 1 §3; ATT&CK mitigations M1051, M1049, M1038 | no |
| Antivirus software monitors to identify malware and prevent or contain incidents; detection by signatures plus heuristics/behavior; keep signatures updated. | NIST glossary "antivirus software"; SP 800-83 §3.4.1; VirusTotal (heuristic engines, known-bad signatures) | no |
| Virus detection methods (EC-Council): scanning (signatures), integrity checking (checksums/baselines), interception (monitor OS requests), code emulation, heuristic analysis. | EC-Council topic "Virus Detection Methods"; SP 800-83 (signatures, behavior); AIDE (integrity checking) | **yes** (`ec-council-specific`) |
| Application allowlisting (SP 800-167): only approved applications run; stops malware and unauthorized software. Windows: App Control for Business, AppLocker. | NIST SP 800-167; NIST glossary "application allowlisting"; Microsoft App Control docs | no |
| Execution prevention and behavior prevention on endpoint are ATT&CK mitigations (M1038, M1040); EDR records process, network, registry and memory telemetry. | ATT&CK M1038, M1040; Microsoft EDR overview | no |
| Ransomware: offline, encrypted, tested backups and golden images; controlled folder access; do not trust backups reachable from the domain. CISA does not encourage paying. | CISA #StopRansomware Guide; Microsoft controlled folder access; ATT&CK M1053 | no |
| Office macros from the internet (Mark of the Web) are blocked by default in Microsoft 365 apps. | Microsoft "Macros from the internet are blocked by default"; Microsoft "Macro malware" | no |
| Incident handling order: preparation → detection and analysis → containment, eradication and recovery → post-incident; containment = stop spread + prevent further damage (disconnect, block C2, disable services). | SP 800-83 §4; SP 800-61 Rev. 2 | no |
| Rebuild (not just disinfect) when attackers had admin access, system files were replaced (Trojan, backdoor, rootkit), the host is unstable, or the extent is unknown. | SP 800-83 Rev. 1 §4.4; CISA ransomware guide (golden images, dropper check before restore) | no |
| Rootkit checks: chkrootkit, rkhunter (Linux); scan from trusted boot media because the infected OS may lie. | chkrootkit; rkhunter; SP 800-83 §4.2.4 (trusted toolkit) | no |
| File integrity monitoring (AIDE, Tripwire-style) detects replaced system files. | AIDE; SP 800-83 (host-based IPS detects file replacement) | no |
| Worms: patch the exploited service, segment networks, block the port (e.g. SMB) at the perimeter; network IPS custom signatures can block known worms. | SP 800-83 §3.4.2 and §4.3.2; CISA WannaCry alert | no |
| IoT botnets: change default credentials, disable Telnet, patch firmware. | CISA Mirai alert; ATT&CK M1027 (Password Policies) | no |
| Removable media: disable AutoRun, scan media. | ATT&CK T1091 mitigations; CISA "Using caution with USB drives" | no |
| Anti-Trojan software and AV names (EC-Council lists vendor products); ClamAV is an open-source AV toolkit. | EC-Council topic "Anti-Trojan Software"; ClamAV docs | **yes** |
