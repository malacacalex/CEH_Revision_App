## Sniffing Concepts

| Fact | Sources | verify |
|---|---|---|
| A sniffer is software (or hardware) that observes and records network traffic; ATT&CK T1040 "Network Sniffing": adversaries capture traffic, often credentials sent over unencrypted protocols. | NIST glossary "sniffer" (CNSSI 4009, SP 800-86); MITRE ATT&CK T1040 | no |
| RFC 4949: "sniffing" is slang for passive wiretapping. Passive wiretapping only observes; active wiretapping alters data or affects the flow. A man-in-the-middle attack is a form of active wiretapping. | RFC 4949 (entries wiretapping, passive/active wiretapping, sniffing, man-in-the-middle attack); NIST glossary "passive wiretapping" and "man-in-the-middle attack" | no |
| On a hub every frame reaches every port, so a NIC in promiscuous mode sees everything; a switch forwards unicast frames only to the port where the destination MAC was learned. EC-Council calls hub sniffing "passive sniffing" and switch sniffing (which needs an attack such as MAC flooding or ARP poisoning) "active sniffing". | Wireshark wiki CaptureSetup/Ethernet; Cisco Catalyst 9300 port security guide (MAC address table); EC-Council course page (terms) | **yes** (passive/active sniffing labels are EC-Council's) |
| Promiscuous mode makes a NIC pass up frames not addressed to it; tcpdump puts the interface in promiscuous mode unless `-p` is given; Linux `ip link set dev X promisc on`. Monitor mode (Wi-Fi) captures all 802.11 frames including management/control frames without joining a network (`tcpdump -I`). | tcpdump(1); ip-link(8); Wireshark wiki CaptureSetup/WLAN | no |
| Legitimate capture points: SPAN / port mirroring on a managed switch (copies traffic of source ports or VLANs to a destination port), RSPAN over a VLAN, and network taps (passive hardware inserted in a link). Mirror ports can drop malformed frames and VLAN tags; taps copy everything on the wire. | Cisco Catalyst 9300 "Configuring SPAN and RSPAN"; Cisco "Configure Catalyst SPAN" (10570-41); Wireshark wiki CaptureSetup/Ethernet | no |
| Cloud sniffing: traffic mirroring services (AWS Traffic Mirroring, GCP Packet Mirroring, Azure vTap) can be abused to sniff VMs. | MITRE ATT&CK T1040 | **yes** (single source) |
| Cleartext protocols expose credentials to sniffers: Telnet, FTP (USER/PASS), HTTP Basic auth (base64, not encryption), POP3, IMAP, SMTP, SNMPv1/v2c community strings, rlogin, NNTP, TFTP (no authentication). dsniff parses passwords from FTP, Telnet, SMTP, HTTP, POP, NNTP, IMAP, SNMP, LDAP, rlogin and others. | dsniff(8); RFC 854, RFC 959, RFC 7617 §4, RFC 1939, RFC 1157, RFC 1350 | no |
| Lawful interception: interception and monitoring of communications authorized by law, carried out by service providers for law enforcement; US CALEA requires carriers to support it. | RFC 3924 (Cisco architecture for lawful intercept); FCC CALEA page | no |
| Sniffing works at the data link layer (layer 2): if layer 2 is compromised, upper layers are exposed unless they are encrypted end to end. | Wireshark wiki CaptureSetup/Ethernet; MITRE ATT&CK T1557 | **yes** (framing) |
| Hardware protocol analyzers (dedicated capture appliances) and SPAN ports are the "legal" ways to see all traffic on a switched network. | EC-Council course page; Wireshark wiki (taps) | **yes** |

## Sniffing Techniques

| Fact | Sources | verify |
|---|---|---|
| MAC flooding: filling the switch's MAC (CAM) table with fake source MACs; many switches then "fail open" and flood frames to all ports like a hub. Tool: macof (dsniff). | macof(8) (Debian); Wireshark wiki CaptureSetup/Ethernet "MAC Flooding"; Juniper port security overview (MAC limiting protects against flooding of the Ethernet switching table) | no |
| Switch port stealing: flooding the LAN with frames whose source MAC is the victim's, so the switch moves the victim's MAC to the attacker's port; useful when ARP poisoning is blocked (static ARP). Ettercap MITM method `port`. | ettercap(8) (Debian); EC-Council course page (term) | **yes** (single technical source) |
| DHCP starvation: flooding DHCP requests from spoofed MACs until the server's address pool is exhausted (DoS; often followed by a rogue server). Tools: dhcpig, Yersinia. | Juniper port security overview; MITRE ATT&CK T1557.003 (DHCP exhaustion); Kali dhcpig page | no |
| Rogue DHCP server / DHCP spoofing: an attacker answers DHCP and hands out its own gateway or DNS server, gaining an AiTM position. DHCPv6 and rogue RAs are the IPv6 equivalents. | MITRE ATT&CK T1557.003; Juniper port security overview; ettercap(8) `dhcp` method | no |
| ARP has no authentication and is stateless; hosts accept unsolicited (gratuitous) replies. ARP spoofing/poisoning maps the attacker's MAC to another host's IP (usually the gateway) to intercept traffic. Tools: arpspoof, Ettercap, Bettercap. | RFC 826; MITRE ATT&CK T1557.002; arpspoof(8); Juniper port security overview | no |
| Gratuitous ARP / ARP Announcement: an ARP request whose sender and target IP are both the announcing host's own address. | RFC 5227 §2.3; MITRE ATT&CK T1557.002 | no |
| MAC spoofing: changing the NIC's MAC to impersonate an allowed device (bypass MAC filtering or port security). Tool: macchanger. Juniper MAC move limiting detects MAC spoofing on access ports. | macchanger(1) and Kali macchanger page; Juniper port security overview | no |
| VLAN hopping, switch spoofing: an attacker negotiates a trunk with DTP from an access port (Cisco ports default to dynamic auto). Fix: `switchport mode access`, `switchport nonegotiate`. | Cisco Catalyst 9300 VLAN guide "Configuring VLAN Trunks"; Kali Yersinia page (DTP, 802.1Q, VTP attacks) | no |
| VLAN hopping, double tagging: frames with two 802.1Q tags sent on the native VLAN; the first switch strips the outer tag and the next switch forwards on the inner VLAN (one-way). Works because the native VLAN is untagged. Fix: unused native VLAN, tag the native VLAN. | Cisco Learning Network "VLAN1 and VLAN Hopping Attack"; Cisco trunk guide (native VLAN untagged, VLAN 1 default) | **yes** (attack described in one Cisco community source) |
| STP attack: a rogue switch sends superior BPDUs to become root bridge and pull traffic through itself. Defenses: BPDU guard on PortFast (edge) ports, root guard on ports that must never lead to the root. | Cisco Catalyst 9300 "Optional Spanning-Tree Features"; Cisco "Enhance STP with Root Guard"; Kali Yersinia page (STP attacks) | no |
| DNS cache poisoning: forged answers accepted by a resolver; the 2008 Kaminsky flaw made it practical; mitigations are source-port randomization plus transaction ID (RFC 5452) and DNSSEC. | CERT/CC VU#800113; RFC 5452; CAPEC-142 | no |
| DNS spoofing on a LAN: a MITM answers DNS queries first with forged replies (dnsspoof, Ettercap dns_spoof, DNSChef as a fake DNS proxy). Other EC-Council variants: intranet, internet (changing the victim's DNS server), proxy server (malicious PAC), cache poisoning. | dnsspoof(8); Kali DNSChef page; MITRE ATT&CK T1557 (DNS manipulation); EC-Council course page ("DNS Poisoning Techniques") | **yes** (four-variant list is EC-Council's) |
| LLMNR/NBT-NS poisoning: when DNS fails, Windows falls back to multicast/broadcast name resolution; an attacker answers and captures NTLM hashes (Responder). Mitigate: disable LLMNR/NetBIOS, enable SMB signing. | MITRE ATT&CK T1557.001; RFC 4795; Kali Responder page | no |
| IPv6 NDP has no built-in authentication; rogue RAs and NDP spoofing are the IPv6 analog of ARP spoofing. Fixes: SEND (RFC 3971), RA Guard (RFC 6105), DHCPv6 Guard. Ettercap `ndp` method. | RFC 4861 §11; RFC 6105; Cisco IPv6 First Hop Security guide; ettercap(8) | no |
| ICMP redirect / IRDP spoofing: forged redirect or router discovery messages advertise the attacker as a better route (half-duplex MITM). | ettercap(8) `icmp` method; EC-Council course page (IRDP) | **yes** |
| SSL stripping: a MITM rewrites HTTPS links to HTTP; HSTS makes the browser refuse plain HTTP for the site. | Kali sslstrip page; RFC 6797; OWASP HSTS Cheat Sheet | no |

## Sniffing Tools

| Fact | Sources | verify |
|---|---|---|
| Wireshark display filters use field names and operators: `==`/`eq`, `!=`/`ne`, `>`, `contains`, `matches`/`~` (PCRE2, case-insensitive), `in {…}` sets, and `&&`/`and`, `\|\|`/`or`, `!`/`not`. Examples: `ip.addr == 10.0.0.5`, `tcp.port in {80,443}`, `http.request.method == "POST"`. | wireshark-filter(4); Wireshark User's Guide "Building Display Filter Expressions"; Wireshark wiki DisplayFilters | no |
| Capture filters use libpcap/BPF syntax (`host`, `net`, `port`, `src`, `dst`, `tcp`, `not arp`), are set before capture and discard packets for good; display filters only hide packets already captured. | Wireshark User's Guide "Filtering while capturing"; pcap-filter(7); Wireshark wiki CaptureFilters | no |
| Field names worth knowing: `eth.addr`, `ip.src`/`ip.dst`/`ip.addr`, `tcp.port`, `tcp.flags.syn`, `tcp.flags.ack`, `udp.port`, `arp.opcode` (1 request, 2 reply), `arp.duplicate-address-detected`, `dns`, `dhcp`, `http.request`, `tcp.stream`. | Wireshark display filter reference (arp, tcp, http, dns, dhcp pages); RFC 826 (opcodes) | no |
| Wireshark features: Follow TCP Stream (rebuilds a conversation), Export Objects (files carried in HTTP/SMB etc.), Statistics > Conversations, Expert Information (flags anomalies such as a duplicate IP address). | Wireshark User's Guide pages "Following Protocol Streams", "Exporting Data", "Conversations", "Expert Information" | no |
| tcpdump options: `-i` interface, `-D` list interfaces, `-n` no name resolution, `-w` write raw pcap, `-r` read file, `-c` stop after count, `-A` ASCII payload, `-X` hex and ASCII, `-e` link-level header (MACs), `-s` snaplen (default 262144), `-p` no promiscuous mode, `-I` monitor mode. | tcpdump(1) (tcpdump.org); Kali tcpdump page | no |
| TShark is Wireshark's command-line version: `-i` capture interface, `-f` capture filter, `-Y` display filter, `-r` read, `-w` write. dumpcap is the capture engine. | tshark(1); dumpcap(1) | no |
| Capture libraries: libpcap (Unix), Npcap (Windows, successor to WinPcap). | Npcap home and guide; Wireshark wiki CaptureSetup | no |
| Ettercap: suite for MITM attacks on a LAN (ARP poisoning, ICMP redirect, DHCP spoofing, port stealing, NDP poisoning; plugins such as dns_spoof). | Kali Ettercap page; ettercap(8) | no |
| Bettercap: Go framework for recon and MITM on 802.11, BLE, IPv4 and IPv6 networks. | Kali Bettercap page; bettercap.org | no |
| dsniff suite: dsniff (password sniffer), arpspoof, macof, dnsspoof, and others. | Kali dsniff page; dsniff(8), arpspoof(8), macof(8), dnsspoof(8) | no |
| Yersinia: layer 2 attack framework (STP, CDP, DTP, DHCP, HSRP, 802.1Q, 802.1X, ISL, VTP). | Kali Yersinia page; Cisco optional STP and VLAN trunk guides (the protocols it abuses) | no |
| Responder: LLMNR, NBT-NS and mDNS poisoner. Driftnet: extracts images from observed TCP streams. DNSChef: DNS proxy ("fake DNS"). dhcpig: DHCP exhaustion. macchanger: change a MAC address. | Kali pages for each tool; MITRE ATT&CK T1557.001 (Responder) | no |
| Nmap `sniffer-detect` NSE script checks whether a host on the local Ethernet has its NIC in promiscuous mode. arpwatch keeps a database of Ethernet/IP pairings and reports changes ("flip flop", "changed ethernet address"). | nmap NSE doc sniffer-detect; arpwatch(8) (Debian); Kali arpwatch page | no |
| tcpdump output: TCP flags print as `S` (SYN), `F` (FIN), `P` (PSH), `R` (RST), `U` (URG), `.` (ACK), so `Flags [S.]` is a SYN-ACK. ARP lines read `who-has X tell Y` (request) and `reply X is-at MAC`; with `-e` the MAC header is printed, showing the request as broadcast. | tcpdump(1) (tcpdump.org, output format section); RFC 826 | no |
| Wireshark ARP fields `arp.opcode`, `arp.duplicate-address-detected` ("Duplicate IP address configured"), `arp.packet-storm-detected`; DHCP message type field `dhcp.option.dhcp` (1 Discover, 2 Offer, 3 Request, 5 ACK per RFC 2131/2132); DNS fields `dns.flags.response`, `dns.qry.name`. | Wireshark dfref arp / dhcp / dns pages; RFC 2131 | no |
| Capture filters (BPF) examples: `arp`, `host 10.0.0.5`, `port 53`, `ether host <mac>`, `not port 22`; the direction qualifiers `src`/`dst`. | pcap-filter(7); Wireshark wiki CaptureFilters; Wireshark User's Guide "Filtering while capturing" | no |

## Sniffing Countermeasures

| Fact | Sources | verify |
|---|---|---|
| Encryption is the main defense against sniffing: TLS (HTTPS, IMAPS/POP3S), SSH instead of Telnet/rlogin, SFTP instead of FTP, SNMPv3 (USM authentication and privacy), IPsec, MACsec (802.1AE) on links. | MITRE ATT&CK M1041 and T1040; RFC 8446; RFC 4253; RFC 3414; RFC 8314; Cisco MACsec guide; IEEE 802.1AE page | no |
| Port security: limit secure MACs per port (default 1), static or sticky learning; violation modes protect (drop silently), restrict (drop, SNMP trap, syslog, counter) and shutdown (err-disable, default). Stops MAC flooding and unknown devices. | Cisco Catalyst 9300 "Port Security"; Juniper port security overview (MAC limiting, persistent/sticky MAC) | no |
| DHCP snooping: ports are trusted (toward servers/uplinks) or untrusted (hosts); server messages (OFFER, ACK, NAK) arriving on untrusted ports are dropped; builds the binding table (MAC, IP, lease, VLAN, port) used by DAI and IP Source Guard; rate limiting helps against starvation. Juniper: access ports untrusted, trunks trusted by default. | Cisco Catalyst 9300 "Configuring DHCP" (IP Addressing guide); Juniper port security overview; MITRE ATT&CK T1557.003 (M1037) | no |
| Dynamic ARP Inspection: intercepts ARP on untrusted ports and drops packets whose IP-to-MAC binding is not in the DHCP snooping table (or an ARP ACL for static hosts); default limit 15 ARP pps on untrusted ports. | Cisco Catalyst 9300 "Configuring Dynamic ARP Inspection"; Juniper DAI page; MITRE ATT&CK T1557.002 (M1037) | no |
| IP Source Guard filters traffic on untrusted ports so the source IP (and optionally MAC) must match the binding table: stops IP spoofing. | Cisco Catalyst 9300 "Configuring IP Source Guard"; Juniper port security overview | no |
| Static ARP entries stop ARP poisoning for key hosts but do not scale. | MITRE ATT&CK T1557.002 (M1035); ip-neighbour(8) (permanent entries) | no |
| 802.1X port-based authentication keeps unauthenticated devices off switch ports (supplicant, authenticator = switch, authentication server = RADIUS). | Cisco Catalyst 9300 "IEEE 802.1x Port-Based Authentication"; IEEE 802.1X page | no |
| STP protection: BPDU guard err-disables a PortFast port that receives a BPDU; root guard puts a port into root-inconsistent (blocked) state if a superior BPDU arrives. | Cisco Catalyst 9300 "Optional Spanning-Tree Features"; Cisco "Enhance STP with Root Guard"; Cisco "PortFast and BPDU Guard" | no |
| VLAN hopping defense: disable DTP (`switchport mode access` / `switchport nonegotiate`), change the native VLAN away from VLAN 1 to an unused VLAN, prune VLANs from trunks, shut unused ports. | Cisco Catalyst 9300 VLAN trunk guide; Cisco Catalyst best practices (24330-185, VLAN 1) | **yes** (native VLAN advice partly from community source) |
| DNS defenses: DNSSEC (origin authentication and integrity, no confidentiality), source-port randomization, DoT (TCP 853) and DoH for privacy of the query path. | RFC 4033; RFC 5452; CERT VU#800113; RFC 7858; RFC 8484; Microsoft DNSSEC overview | no |
| IPv6 first-hop security: RA Guard, DHCPv6 Guard, ND inspection, IPv6 source guard. | RFC 6105; Cisco IPv6 First Hop Security guide; Juniper port security overview | no |
| LLMNR/NBT-NS: disable if not needed, block by host firewall, enable SMB signing. | MITRE ATT&CK T1557.001; RFC 4795 | no |
| HSTS forces HTTPS and defeats SSL stripping after the first visit (preload list covers the first visit). | RFC 6797; OWASP HSTS Cheat Sheet | no |
| Sniffer detection: promiscuous-mode checks (ARP method: send ARP to a fake broadcast MAC; only a promiscuous NIC answers; Nmap sniffer-detect), DNS method (sniffers doing reverse lookups on observed IPs), ping method with a wrong MAC, latency method. Detect ARP poisoning with arpwatch, IDS (ARP anomalies), Wireshark Expert Info (duplicate IP). | nmap sniffer-detect; arpwatch(8); Wireshark ARP field reference (duplicate-address-detected); NIST SP 800-94 (IDS); EC-Council course page ("Sniffer Detection Techniques") | **yes** (method names are EC-Council's) |
| Network segmentation and switched networks reduce what one sniffer sees; ATT&CK M1030. | MITRE ATT&CK T1040 (M1030); MITRE M1030 page | no |
