# Research: M10 Denial-of-Service

Scope: the three sections in `content/modules/m10/meta.json`. The public CEH v13 course page lists the module's
key topics (DoS attack, DDoS attack, botnets, DoS/DDoS attack techniques, attack toolkits, detection techniques,
protection tools, protection services). That list is used for scope only; all wording below is ours, from
public primary sources. The module is written at a conceptual, defensive level: what each attack looks like,
how to recognize it and how to mitigate it. No attack tooling instructions.

and labels (tag `ec-council-specific`) and facts backed by a single source.

## DoS/DDoS Concepts

| Fact | Sources | verify |
|---|---|---|
| DoS = preventing authorized access to resources or delaying time-critical operations; DDoS = the same from many coordinated sources, usually a botnet, which makes blocking single addresses useless. | NIST CSRC glossary "denial of service" and "distributed denial of service"; CISA "Understanding Denial-of-Service Attacks" | no |
| DoS hits availability, the A of CIA. | NIST glossary "availability"; CISA "Understanding Denial-of-Service Attacks" | no |
| Symptoms: unusually slow network performance, one site unavailable, no site reachable; detection is done by traffic monitoring (firewall, IDS, alerts on anomalous load). | CISA "Understanding Denial-of-Service Attacks"; CISA/FBI/MS-ISAC "Understanding and Responding to DDoS Attacks" | no |
| Three categories: volumetric (consume bandwidth: UDP floods, ICMP floods, amplification), protocol (exploit L3/L4 protocol weaknesses and state: SYN floods, fragmentation), application layer (L7: HTTP floods, low-and-slow). | CISA/FBI/MS-ISAC DDoS guide; Microsoft "Types of attacks Azure DDoS Protection mitigates"; Cloudflare "What is a DDoS attack?" | no |
| Units: volumetric in bits per second, protocol in packets per second, application in requests per second. | EC-Council framing; consistent with vendor reporting (Cloudflare) | **yes** |
| ATT&CK: T1498 Network DoS (T1498.001 direct network flood, T1498.002 reflection amplification) and T1499 Endpoint DoS (.001 OS exhaustion flood, .002 service exhaustion flood, .003 application exhaustion flood, .004 application or system exploitation), both under Impact (TA0040). | MITRE ATT&CK T1498, T1499 and sub-techniques; TA0040 | no |
| Botnet = network of compromised hosts (bots, zombies) controlled by a bot master through command and control (C2); adversaries build or rent botnets. | NIST glossary "botnet"; MITRE T1583.005 and T1584.005; Cloudflare "What is a DDoS botnet?" | no |
| Mirai (2016) recruited IoT devices through a short list of default usernames and passwords over Telnet; its source code was published, spawning variants. | CISA alert TA16-288A; Cloudflare "What is the Mirai botnet?" | no |
| DDoS can hide other intrusions or be used for extortion (ransom DDoS). | Cloudflare "Ransom DDoS attack"; CISA/FBI/MS-ISAC DDoS guide | **yes** (one detailed source) |
| Botnet scanning methods (random, hit-list, topological, local subnet, permutation) and code propagation models (central source, back-chaining, autonomous). | EC-Council framing only (course page "Botnets" topic) | **yes** |

## DoS/DDoS Attack Techniques

| Fact | Sources | verify |
|---|---|---|
| SYN flood: many SYNs (often spoofed) leave half-open connections in SYN-RECEIVED until the backlog fills and legitimate clients are refused. | RFC 4987 §2; Cloudflare "SYN flood attack"; AWS DDoS resiliency whitepaper | no |
| Reflection: spoofed requests with the victim's source address go to third-party servers (reflectors), which answer the victim. Amplification: the answer is much larger than the request. Called DRDoS. Mostly UDP because there is no handshake. | MITRE T1498.002; CISA TA14-017A; Cloudflare "DNS amplification" | no |
| Bandwidth amplification factors (CISA TA14-017A): DNS 28–54, NTP 556.9, SNMPv2 6.3, NetBIOS 3.8, SSDP 30.8, CharGEN 358.8, QOTD 140.3, LDAP 46–55, CLDAP 56–70, TFTP 60, Memcached 10,000–51,000, WS-Discovery 10–500. | CISA TA14-017A (table); Cloudflare blog "Memcrashed" (memcached up to about 51,000x) | no |
| NTP amplification abuses the `monlist` query (CVE-2013-5211), fixed in ntpd 4.2.7p26. | NVD CVE-2013-5211; CISA TA14-013A | no |
| DNS amplification uses open resolvers; fix: no open recursion (BCP 140 / RFC 5358), response rate limiting. | CISA TA13-088A; RFC 5358; Cloudflare "DNS amplification" | no |
| Memcached reflection used UDP port 11211 (2018). | CISA TA14-017A; Cloudflare blog "Memcrashed" | no |
| Smurf: ICMP echo requests to a directed broadcast address with the victim's spoofed source, so every host replies to the victim. Fix: routers drop directed broadcasts by default (RFC 2644, BCP 34). | Cloudflare "Smurf attack"; RFC 2644; Imperva "Smurf attack" | no |
| Fraggle: the UDP variant of smurf (echo/chargen to broadcast). | EC-Council framing; no reachable second source | **yes** |
| Ping of death: an IP datagram reassembled above the 65,535-byte maximum crashes old stacks (CVE-1999-0128). | NVD CVE-1999-0128; RFC 791 (total length field); Cloudflare "Ping of death" | no |
| Teardrop: overlapping IP fragments that old stacks could not reassemble (CVE-1999-0015). | NVD CVE-1999-0015; Imperva "IP fragmentation attack (teardrop)" | no |
| Land attack: packet with the same source and destination address and port (CVE-1999-0016). | NVD CVE-1999-0016; EC-Council framing for the name | **yes** |
| UDP flood and ICMP flood: volumetric, exhaust bandwidth and the host's reply work. | Cloudflare "UDP flood" and "Ping (ICMP) flood"; Microsoft "Types of attacks" | no |
| HTTP flood: many legitimate-looking GET or POST requests; hard to filter because each request is valid. | Cloudflare "HTTP flood"; Imperva "HTTP flood"; MITRE T1499.002 | no |
| Slowloris: opens many connections and keeps each one alive with partial headers, exhausting the server's connection pool with little bandwidth (CVE-2007-6750; Apache fix mod_reqtimeout). | Cloudflare "Slowloris"; NVD CVE-2007-6750; Imperva "Slowloris" | no |
| R.U.D.Y. is the slow POST relative of Slowloris (body sent very slowly). | Cloudflare "Low and slow attack" | **yes** |
| HTTP/2 Rapid Reset (CVE-2023-44487): opening and cancelling streams very fast consumes server resources; record attacks in 2023. | CISA alert 2023-10-10; NVD CVE-2023-44487; Cloudflare blog "HTTP/2 Rapid Reset" | no |
| LOIC: open-source flooding tool associated with hacktivist campaigns, does not hide the sender's IP; HOIC: HTTP flood successor with booster scripts. | Cloudflare "LOIC"; Imperva "LOIC" and "HOIC" | HOIC details **yes** |
| Permanent DoS (PDoS, phlashing): damages firmware or hardware so the device must be repaired or replaced. | MITRE T1495 Firmware Corruption (related technique); EC-Council framing for the terms | **yes** |
| Peer-to-peer DDoS (clients of a P2P hub told to connect to the victim), pulse-wave and multi-vector attacks. | EC-Council framing; no reachable second primary source | **yes** |

## DoS/DDoS Countermeasures

| Fact | Sources | verify |
|---|---|---|
| RFC 4987 lists SYN flood defenses: filtering, bigger backlog, shorter SYN-RECEIVED timer, recycling the oldest half-open TCB, SYN cache, SYN cookies, hybrids, firewalls and proxies. | RFC 4987 §3; Cloudflare blog "SYN packet handling in the wild" | no |
| SYN cookies avoid keeping state for half-open connections; Linux sends them only when the SYN backlog overflows (`net.ipv4.tcp_syncookies`, default 1). | RFC 4987 §3.6; Linux kernel ip-sysctl documentation | no |
| Ingress filtering (BCP 38, RFC 2827) drops packets whose source address is not valid for the network they come from, which stops spoofing at the edge; BCP 84 (RFC 3704) extends it to multihomed networks with uRPF. | RFC 2827; RFC 3704; NIST SP 800-189; CISA TA14-017A | no |
| Egress filtering stops your own hosts sending spoofed or unwanted traffic out (not becoming a DDoS source). | NIST glossary "egress filtering"; RFC 2827 | no |
| Remotely triggered black hole (RTBH) routing drops all traffic to (or from) an address, often with the ISP; the victim goes offline too. BLACKHOLE community 65535:666. | RFC 5635; RFC 7999; Cloudflare "Blackhole routing"; CISA TA14-017A | no |
| Amplifier hygiene: disable unused UDP services, close open resolvers, DNS response rate limiting, patch (monlist), rate-limit UDP services. | CISA TA14-017A; RFC 5358; NVD CVE-2013-5211 | no |
| Detection: flow data (bytes per packet, packets per second anomalies), large unsolicited UDP responses, IDS alerts. | CISA TA14-017A; CISA "Understanding Denial-of-Service Attacks" | no |
| Application layer: WAF, rate limiting (nginx `limit_req`, default rejection status 503), request timeouts against slow attacks (Apache mod_reqtimeout). | nginx limit_req docs; Apache mod_reqtimeout docs; Microsoft "Types of attacks"; Cloudflare "Rate limiting" | no |
| Absorb: anycast spreads the flood over many data centers; scrubbing/protection services (Cloudflare, AWS Shield Standard/Advanced, Azure DDoS Protection, Google Cloud Armor, Akamai). | Cloudflare "Anycast network" and "DDoS mitigation"; AWS Shield docs; Azure DDoS Protection overview; Cloud Armor overview | no |
| DOTS (RFC 8811/8612) lets a network under attack signal a mitigation provider. | RFC 8811; RFC 8612 | no |
| Response plan: know your service and upstream defenses, contact ISP/provider, scale, test the plan. | NCSC DoS guidance; CISA/FBI/MS-ISAC DDoS guide; NIST SP 800-61r3 | no |
| Botnet prevention: change default credentials, patch IoT devices, block Telnet exposure. | CISA TA16-288A; Cloudflare "Mirai botnet" | no |
| ATT&CK mitigation M1037 Filter Network Traffic applies to T1498 and T1499. | MITRE M1037; MITRE T1498 | no |
| EC-Council strategies: absorb the attack, degrade services, shut down services; deflect with honeypots; post-attack forensics (traffic pattern analysis, traceback). Detection: activity profiling, sequential change-point detection, wavelet-based signal analysis. | EC-Council framing only | **yes** |
