# Research: M13 Hacking Web Servers

Scope: the four sections in `content/modules/m13/meta.json`. The public CEH v13 course page lists the module's
key topics (web server architecture, web server vulnerabilities, web server attacks, DNS server hijacking, web
cache poisoning, footprinting/banner grabbing, directory brute forcing, vulnerability scanning, web server
password hacking, attack tools, countermeasures, detecting web server hacking attempts, web server security
tools) and four labs, one of them "web server hacking using AI". That list is used for scope only; all wording
below is ours, from public primary sources.

This module is written at exam-knowledge level from the **defender's** point of view: what the attack classes
look like, which tool a tester would name, and how to harden, patch and detect. No exploit code or attack
walkthroughs. Primary sources: NIST SP 800-44 Ver. 2 (securing public web servers), SP 800-40 Rev. 4 (patch
management), SP 800-123, the Apache httpd / nginx / IIS documentation, OWASP WSTG (information gathering and
configuration testing chapters), OWASP cheat sheets, MITRE ATT&CK (T1190, T1505.003 and related), CWE, CISA.

Checked on 2026-09-24 with curl and a browser User-Agent. All cited URLs return 200, except GitHub WSTG pages
(429 rate limit; each file confirmed through raw.githubusercontent.com). Removed (404): NIST glossary
"defacement", "reverse_proxy", "virtual_patching", "web_shell"; old WSTG file names (the chapters were
renamed, e.g. `06-Test_HTTP_Methods` → `06-HTTP_Methods`); `owasp.org/www-project-modsecurity-core-rule-set`
(use coreruleset.org); the NSA web shell PDF on media.defense.gov (403 and no Wayback capture: replaced by the
nsacyber GitHub repository). `verify: true` marks EC-Council-specific lists or framing and single-source facts.

## Web Server Concepts

| Fact | Sources | verify |
|---|---|---|
| A web server accepts HTTP(S) requests and returns resources; the document root is the directory mapped to `/`; virtual hosts serve several sites from one server (name-based uses the `Host` header). | Apache "URL mapping" and "Virtual hosts" docs; nginx "How nginx processes a request"; RFC 9110 §7.2 (Host) | no |
| Apache httpd: modular, per-directory `.htaccess` overrides, Multi-Processing Modules (prefork, worker, event) decide how requests map to processes/threads. | Apache MPM doc; Apache `.htaccess` howto | no |
| nginx: event-driven, one master process and several worker processes; widely used as reverse proxy and load balancer (`proxy_pass`). | nginx Beginner's Guide; nginx proxy module; NGINX admin guide "reverse proxy" | no |
| IIS: kernel-mode listener HTTP.sys queues requests; WAS and the WWW service configure and start worker processes (w3wp.exe) grouped in application pools; each pool can run under its own low-privilege identity. | Microsoft "Introduction to IIS architecture"; Microsoft "Application pool identities" | no |
| Web server vs application server vs reverse proxy: a reverse proxy sits in front of servers, can rewrite banners, terminate TLS, cache and filter. | NIST SP 800-44 v2 §8 (reverse proxy, banners); nginx proxy module | no |
| The `Server` response header describes the software handling the request; RFC 9110 warns that detailed version info makes known-vulnerability targeting easier. | RFC 9110 §10.2.4; MDN "Server" header | no |
| Default banner verbosity: Apache `ServerTokens` default `Full`; nginx `server_tokens` default `on` (version shown). `ServerTokens Prod` / `server_tokens off` hide version. | Apache core docs; nginx core module docs | no |
| Directory listing defaults: nginx `autoindex off`; Apache lists a folder only if `Options Indexes` is on and no index file exists; IIS `directoryBrowse enabled` is false by default. | nginx autoindex module; Apache mod_autoindex; Microsoft IIS directoryBrowse | no |
| Why web servers are exposed: internet-facing, large attack surface, default installs with samples and services, misconfiguration, unpatched software, weak remote admin. OWASP A05 (misconfiguration) and A06 (vulnerable components). | NIST SP 800-44 v2 §2 and §5; OWASP Top 10 A05:2021 and A06:2021 | no |
| NIST SP 800-44 v2 lists threat types for public web servers, including defacement, denial of service, exploitation of software bugs and misconfiguration, and use of the server as a pivot. | NIST SP 800-44 v2 §2 | no |
| Status pages: Apache `mod_status` / `mod_info` and nginx `stub_status` reveal internal state and must be restricted. | Apache mod_status and mod_info docs; nginx stub_status docs | no |
| HTTP methods: `TRACE` echoes the request (Apache `TraceEnable` default on); `OPTIONS` lists allowed methods; `PUT`/`DELETE` change resources. | RFC 9110 §9.3; Apache core `TraceEnable`; MDN TRACE and OPTIONS | no |

## Web Server Attacks

| Fact | Sources | verify |
|---|---|---|
| Directory (path) traversal: `../` sequences or encoded variants reach files outside the web root (CWE-22). Apache 2.4.49 had a real path traversal (CVE-2021-41773), listed in CISA KEV. | OWASP "Path Traversal"; CWE-22; Apache 2.4 vulnerabilities page; CISA KEV | no |
| Directory listing exposure (CWE-548) and backup/unreferenced files (`.bak`, `.old`, archives; CWE-530) leak source and credentials. | CWE-548; CWE-530; WSTG 4.2.4 "Review Old Backup and Unreferenced Files" | no |
| Verbose error messages leak stack traces, versions, paths (CWE-209). | CWE-209; WSTG 4.8.1 "Improper Error Handling"; OWASP Error Handling cheat sheet | no |
| HTTP response splitting: unvalidated CR/LF in data placed into a response header lets the attacker start a second response (CWE-113). | OWASP "HTTP Response Splitting"; CWE-113; WSTG 4.7.15 | no |
| Web cache poisoning: attacker makes a cache store a harmful response that is then served to other users; unkeyed inputs are the classic cause. | OWASP "Cache Poisoning"; PortSwigger "Web cache poisoning"; CAPEC-141 | no |
| HTTP request smuggling: front end and back end disagree on where a request ends (Content-Length vs Transfer-Encoding), CWE-444. | PortSwigger "HTTP request smuggling"; CWE-444; RFC 9112 §6.3 | no |
| DoS/DDoS on web servers: volumetric and reflection/amplification floods (T1498/T1498.002) vs application-layer service exhaustion (T1499.002). Slow HTTP (Slowloris) holds connections open with partial headers. | MITRE T1498, T1498.002, T1499.002; OWASP DoS cheat sheet; Nmap `http-slowloris-check` | no |
| HTTP/2 Rapid Reset (CVE-2023-44487) is a recent application-layer DDoS against HTTP/2 servers. | CISA alert 2023-10-10; RFC 9113 | no |
| DNS server hijacking: attacker changes DNS records (A, MX, NS) after getting DNS admin credentials, so users reach an attacker's server. MITRE: compromise DNS server (T1584.002). | CISA ED 19-01; MITRE T1584.002 | no |
| DNS amplification: small spoofed queries to open resolvers produce large responses aimed at the victim. | CISA alert "DNS Amplification Attacks"; MITRE T1498.002 | no |
| Website defacement = unauthorized change of the site's content, usually for a message (MITRE T1491.002 external defacement). | MITRE T1491.002; NIST SP 800-44 v2 §2 | no |
| Web shell = script placed on a web server to run commands through HTTP; persistence technique T1505.003. Detection hint: web server process (w3wp.exe, httpd, nginx) spawning shells. | MITRE T1505.003; CISA alert TA15-314A; NSA/ASD "Mitigating Web Shells" repo | no |
| Exploit Public-Facing Application (T1190) covers exploiting a bug, glitch or misconfiguration in an internet-facing host, often a web server. | MITRE T1190; CISA KEV | no |
| Web server password attacks: brute force / guessing of admin logins, remote admin (SSH, FTP, control panels), default credentials. | MITRE T1110, T1110.001; CWE-1392 (default credentials); CWE-521 | no |
| SSRF: the server is tricked into sending requests to internal or cloud-metadata endpoints (CWE-918, OWASP A10:2021). | OWASP SSRF prevention cheat sheet; CWE-918; PortSwigger SSRF | no |
| Man-in-the-middle / sniffing of unencrypted admin or site traffic (T1557). Defense: TLS everywhere + HSTS. | MITRE T1557; RFC 6797; OWASP TLS cheat sheet | no |
| EC-Council groups web server attacks as DoS/DDoS, DNS server hijacking, DNS amplification, directory traversal, MITM/sniffing, phishing, defacement, misconfiguration, response splitting, cache poisoning, SSH brute force, password cracking, SSRF and others. | EC-Council CEH course page (scope only) | yes (EC list, tag `ec-council-specific`) |

## Web Server Attack Methodology

| Fact | Sources | verify |
|---|---|---|
| EC-Council methodology: information gathering → web server footprinting/banner grabbing → website mirroring → vulnerability scanning → session hijacking → web server password hacking (order and names are EC framing). | EC-Council CEH course page (topics) | yes (tag `ec-council-specific`) |
| Banner grabbing = capturing banner information (application type and version) sent by a port when a connection opens. | NIST glossary "banner grabbing" (SP 800-115); WSTG 4.1.2 "Fingerprint Web Server" | no |
| Fingerprinting beyond banners: header order, error page content, response to malformed requests, `X-Powered-By`, cookies; tools Netcat, curl `-I`, Nmap `-sV`, WhatWeb, Netcraft site report. | WSTG 4.1.2; Nmap version detection; Kali WhatWeb; MDN X-Powered-By | no |
| Metafiles: `robots.txt` (RFC 9309) is advisory for crawlers, not access control; `/.well-known/security.txt` (RFC 9116) lists a disclosure contact. | RFC 9309; RFC 9116; WSTG 4.1.3 | no |
| Website mirroring copies a site for offline analysis: HTTrack, `wget --mirror`. | Kali HTTrack; GNU Wget manual | no |
| Directory brute forcing / forced browsing: Gobuster, DirBuster, dirb, ffuf use wordlists; MITRE T1595.003 (wordlist scanning). Nmap `http-enum` checks known paths. | Kali gobuster, dirb, ffuf; MITRE T1595.003; Nmap http-enum | no |
| Vulnerability scanning of web servers: Nikto (server + CGI checks, outdated versions, dangerous files), Nessus/OpenVAS, Skipfish; MITRE T1595.002. Scanning is noisy and shows in access logs. | Kali Nikto; sullo/nikto; Kali skipfish; MITRE T1595.002 | no |
| HTTP method testing: Nmap `http-methods` sends OPTIONS then tests risky methods; WSTG 4.2.6. | Nmap http-methods; WSTG 4.2.6 | no |
| WAF detection before testing: wafw00f fingerprints WAF products. | Kali wafw00f | no |
| Password attacks on web logins: Hydra supports HTTP(S) form and basic auth among many protocols. | Kali Hydra; MITRE T1110 | no |
| Shodan and Censys index banners, so exposure can be found without touching the target (passive). | Shodan; WSTG 4.1.2 | no |
| TLS configuration testing: sslscan, testssl.sh, SSL Labs. | Kali sslscan; testssl.sh; Qualys SSL Labs | no |
| AI in v13: EC-Council lists a lab on web server hacking using AI; defenders use the same assistants to summarize scan output and draft hardening checklists, always verifying the output. | EC-Council CEH course page; OWASP Top 10 for LLM apps | yes (tag `ec-council-specific`) |

## Web Server Attack Countermeasures

| Fact | Sources | verify |
|---|---|---|
| SP 800-44 hardening: dedicated single-purpose host, remove unnecessary services and sample content, content on a separate partition, disable directory listing and symbolic links, least privilege, change banners, file integrity checking, logging, backups. | NIST SP 800-44 v2 (executive summary, §4-§5, §9); NIST SP 800-123 | no |
| Place public web servers in a DMZ (perimeter segment between internal and external networks). | NIST glossary "demilitarized zone"; NIST SP 800-44 v2 §8; NIST SP 800-41 r1 | no |
| Hardening = eliminate means of attack by patching and turning off nonessential services. | NIST glossary "hardening" (SP 800-152); CIS Benchmarks (Apache, nginx, IIS) | no |
| Banner reduction: Apache `ServerTokens Prod` + `ServerSignature Off`; nginx `server_tokens off`; IIS removal of headers via request filtering / custom headers. Security through obscurity only: still patch. | Apache core; nginx core; Microsoft IIS custom headers; RFC 9110 §10.2.4 | no |
| Disable TRACE (`TraceEnable off`) and restrict methods (IIS request filtering `verbs`, nginx `limit_except`). | Apache core; Microsoft IIS requestFiltering verbs; nginx core module; WSTG 4.2.6 | no |
| Slow-HTTP DoS mitigations: Apache `mod_reqtimeout` (`RequestReadTimeout`), nginx `client_header_timeout`/`limit_conn`/`limit_req`, IIS Dynamic IP Restrictions; upstream DDoS protection/CDN. | Apache mod_reqtimeout; nginx limit_req and limit_conn; Microsoft IIS dynamicIpSecurity; CISA DDoS guide | no |
| Patch management = notification, identification, deployment, installation and verification of patches, hotfixes and service packs. | NIST glossary "patch management" (CNSSI 4009); NIST SP 800-40 r4 | no |
| Hotfix = Microsoft's term for patch (SP 800-44); service pack = tested cumulative set of hotfixes and updates. | NIST glossary "hotfix"; Microsoft "standard terminology for software updates" | no |
| SP 800-40 r4 risk responses: accept, mitigate (patch, disable feature, extra controls), transfer (insurance, SaaS), avoid (uninstall/decommission). Maintenance plans: routine patching, emergency patching, emergency mitigation, unpatchable assets. | NIST SP 800-40 r4 §2.1 and §3.5 | no |
| Patch steps: prepare (prioritize, acquire, validate, test), deploy, verify deployment, monitor. | NIST SP 800-40 r4 §2.3 | no |
| Prioritize known-exploited vulnerabilities: CISA KEV catalog and BOD 22-01 due dates. | CISA KEV; CISA BOD 22-01 | no |
| Web application firewall / virtual patching: ModSecurity with the OWASP Core Rule Set filters attacks while a patch is pending. | OWASP "Web Application Firewall"; coreruleset.org; ModSecurity repo; MITRE M1050 | no |
| TLS: modern protocol versions and ciphers (Mozilla guideline, SP 800-52 r2), HSTS (RFC 6797) to stop downgrade to HTTP. | NIST SP 800-52 r2; Mozilla Server Side TLS; RFC 6797; OWASP HSTS cheat sheet | no |
| Security headers (HSTS, X-Content-Type-Options, CSP, and removal of `X-Powered-By`/`Server` detail). | OWASP HTTP Headers cheat sheet; OWASP Secure Headers project; WSTG 4.2.14 | no |
| Detect web server hacking: file integrity monitoring of web root and configs (AIDE, OSSEC, Tripwire-style), log review (combined log format), alert on web server processes spawning shells. | NIST SP 800-44 v2 §8.2.2 and §9; AIDE; OSSEC; MITRE T1505.003 detection; OWASP Logging cheat sheet | no |
| Web shell mitigation: least privilege for the web server account, prevent writes to web directories, file integrity monitoring, patch internet-facing apps. | NSA/ASD Mitigating-Web-Shells repo; CISA TA15-314A; MITRE T1505.003 mitigations | no |
| DNS hijacking defense: MFA on DNS/registrar accounts, audit DNS records, monitor Certificate Transparency logs. | CISA ED 19-01 | no |
| ATT&CK mitigations for T1190: application isolation and sandboxing (M1048), exploit protection/WAF (M1050), network segmentation (M1030), privileged account management (M1026), update software (M1051), vulnerability scanning (M1016). | MITRE T1190 mitigations; MITRE M1048, M1050, M1030, M1026, M1051, M1016 | no |
| IIS application pool identities isolate sites with a virtual low-privilege account per pool. | Microsoft "Application pool identities"; Microsoft IIS architecture | no |
