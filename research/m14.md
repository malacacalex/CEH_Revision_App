# Research: M14 Hacking Web Applications

Scope: the five sections in `content/modules/m14/meta.json`. The public CEH v13 course page lists the module's key
topics (web application, OWASP Top 10 application security risks 2021, web application attacks, footprint web
infrastructure, analyze web applications, bypass client-side controls, attack access controls, attack web services,
web API, webhooks, web API hacking methodology, API security risks and solutions, web application security testing,
fuzz testing, encoding schemes, countermeasures, security testing tools) and six labs, one of them "web application
hacking using AI". That list is used for scope only; all wording below is ours, from public primary sources.

Written at CEH recognition level with a **defensive** framing (wave 3 retry): for each weakness, what it is, how it
shows up in requests, responses or logs, and the OWASP Cheat Sheet countermeasure. Tools are covered for recognition
(what the tool is for, what an option or output line means). No attack procedures, exploit code or payload lists.
SQL injection is covered by M15 and web server attacks by M13: they appear here only as cross-references.

Primary sources: OWASP Top 10:2025 and 2021, OWASP API Security Top 10 2023, OWASP Cheat Sheet Series, OWASP WSTG
(GitHub master), OWASP community pages, CWE and CAPEC, MITRE ATT&CK, MDN, RFCs (6265, 6454, 6797, 7519, 8725, 9110,
6585, 3986, 4648), NIST (SP 800-218, 800-95, CSRC glossary), CISA Secure by Design alerts, GitHub and Stripe webhook
docs, Standard Webhooks spec, NSA/ASD "Mitigating Web Shells", Burp Suite, ZAP and Kali tool documentation.

limit; WSTG files confirmed through the GitHub contents API). Removed (404): `owasp.org/www-project-api-security-top-10/`

## Web Application Concepts

| Fact | Sources | verify |
|---|---|---|
| A web application runs on a server and is used through a browser; typical tiers are presentation (browser/web server), application/logic (application server) and data (database). | IBM "Three-tier architecture"; Microsoft Azure "N-tier architecture style"; AWS "What is a web application" | no |
| HTTP is a stateless request/response protocol; a request has a method, target, headers and optional body, a response has a status code, headers and body. | RFC 9110; MDN "HTTP messages" and "Overview of HTTP" | no |
| Methods: GET and HEAD retrieve, POST submits, PUT replaces, DELETE removes, PATCH modifies, OPTIONS lists communication options, TRACE echoes the request (loop-back), CONNECT opens a tunnel. GET, HEAD, OPTIONS, TRACE are "safe". | RFC 9110 §9; MDN "HTTP request methods"; IANA HTTP method registry | no |
| Status classes: 2xx success, 3xx redirection (Location header), 4xx client error, 5xx server error. 401 = not authenticated (with WWW-Authenticate), 403 = authenticated or not but refused, 405 = method not allowed, 429 = too many requests (RFC 6585, may carry Retry-After), 500 = internal server error. | RFC 9110 §15; RFC 6585 §4; MDN status pages | no |
| Sessions: HTTP has no state, so the server issues a session ID, usually in a cookie; whoever holds a valid ID is treated as that user. | MDN "Using HTTP cookies"; OWASP Session Management cheat sheet | no |
| Cookie attributes: `Secure` (HTTPS only), `HttpOnly` (not readable by JavaScript), `SameSite` (Strict, Lax, None; None requires Secure), `Domain`, `Path`, `Expires`/`Max-Age`; prefixes `__Host-` and `__Secure-` add constraints. | RFC 6265; MDN "Set-Cookie"; OWASP Session Management cheat sheet; IETF draft rfc6265bis | no |
| Same-origin policy: origin = scheme + host + port; scripts from one origin cannot read responses from another. | RFC 6454; MDN "Same-origin policy"; MDN "Origin" glossary | no |
| CORS relaxes SOP through response headers (`Access-Control-Allow-Origin`, `-Credentials`, `-Methods`); the wildcard `*` cannot be combined with credentials; reflecting any Origin with credentials is a misconfiguration (CWE-942). | MDN "CORS"; Fetch standard; CWE-942; WSTG 4.11.7 | no |
| Web services: SOAP uses an XML envelope described by WSDL; REST uses resources, HTTP verbs and usually JSON, and is stateless; GraphQL exposes one endpoint with a typed schema queried by the client; gRPC uses HTTP/2 and Protocol Buffers. | W3C SOAP 1.2; W3C WSDL 2.0; MDN "REST"; graphql.org; grpc.io; AWS "SOAP vs REST" | no |
| Common front-end parts: reverse proxy, load balancer, CDN/cache, API gateway, WAF; each can change headers and trust boundaries. | Microsoft "API gateway pattern"; OWASP WSTG 4.1.10 "Map Application Architecture" | no |
| Encoding is not encryption: URL (percent) encoding `%2F`, HTML entities `&lt;`, Base64 (RFC 4648), Unicode/UTF-8, hex. Double encoding (`%252F`) is a filter-evasion class; canonicalize before validating. | RFC 3986 §2.1; RFC 4648; OWASP Input Validation cheat sheet; CAPEC-267 (alternate encoding) | no |
| Client-side controls (hidden fields, disabled buttons, JavaScript validation, maxlength) are not security controls: every value can be changed in a proxy. | OWASP "Web Parameter Tampering"; CWE-602 (client-side enforcement of server-side security); WSTG 4.10 | no |
| JWT: three Base64url parts `header.payload.signature`; payload is readable by anyone; the signature must be verified and the algorithm pinned (reject `alg: none`). | RFC 7519; RFC 8725 (JWT BCP); OWASP JWT cheat sheet; jwt.io | no |
| OAuth 2.0 is delegated authorization (access tokens); OpenID Connect adds authentication (ID token); PKCE protects the authorization code for public clients. | RFC 6749; OpenID Connect Core 1.0; RFC 7636; RFC 9700 | no |

| A07 Authentication Failures: credential stuffing and brute force allowed, weak or default passwords, session IDs in URLs, no invalidation at logout. | A08 Software or Data Integrity Failures: trusting unsigned updates, CDN scripts without integrity, insecure deserialization. | A09 Security Logging and Alerting Failures: logins, access-control failures and input-validation failures not logged or not alerted; logs vulnerable to injection (CWE-117). | OWASP A09:2025; OWASP Logging cheat sheet; CWE-778 | no |
| A10 Mishandling of Exceptional Conditions (new): improper error handling, failing open (CWE-636), sensitive error messages (CWE-209). | XSS (CWE-79): reflected (in the immediate response), stored (saved and served to others), DOM-based (client-side sink such as `innerHTML`). Recognize: script or event-handler markup in a parameter echoed unencoded. Prevent: contextual output encoding, safe sinks, CSP, HttpOnly. | OWASP "Types of XSS"; OWASP XSS and DOM XSS prevention cheat sheets; CWE-79; PortSwigger XSS | no |
| CSRF (CWE-352): a forged cross-site request rides the victim's cookies to change state. Prevent: synchronizer token, SameSite cookies, Origin/Referer check, re-authentication for sensitive actions. | OWASP CSRF community page; OWASP CSRF Prevention cheat sheet; CWE-352 | no |
| SSRF (CWE-918): the server fetches a URL chosen by the user and reaches internal services or cloud metadata (169.254.169.254). Recognize: URL-valued parameters, outbound requests from app servers to internal ranges. Prevent: allowlist destinations, block redirects, segment the network. | OWASP SSRF Prevention cheat sheet; CWE-918; PortSwigger SSRF; OWASP API7:2023 | no |
| Path traversal (CWE-22) and file inclusion (CWE-98): `../` or encoded forms in a file parameter; LFI reads local files, RFI loads a remote file (PHP `allow_url_include` is Off by default). | OS command injection (CWE-78): shell metacharacters (`;`, `\|`, `&&`, backticks) in input passed to a shell. Prevent: call APIs instead of a shell, parameterize, allowlist. | XXE (CWE-611): an XML parser resolves external entities declared in a DOCTYPE and reads files or makes requests. Prevent: disable DTDs/external entities. | OWASP XXE Prevention cheat sheet; CWE-611; PortSwigger XXE | no |
| Insecure deserialization (CWE-502): untrusted serialized objects rebuilt on the server. Recognize: Java streams begin `AC ED 00 05` (Base64 `rO0`), PHP `O:` objects, Python pickle. Prevent: avoid native deserialization of untrusted data, sign, allowlist classes. | OWASP Deserialization cheat sheet; CWE-502; Python pickle docs; Oracle serialization filtering | no |
| Clickjacking (CWE-1021): the target page is loaded in an invisible frame. Prevent: CSP `frame-ancestors` and `X-Frame-Options: DENY`/`SAMEORIGIN`. | OWASP Clickjacking Defense cheat sheet; RFC 7034; MDN X-Frame-Options | no |
| Open redirect (CWE-601): a redirect parameter sends users to any site (phishing). Prevent: avoid user-controlled destinations or map to an allowlist. | OWASP Unvalidated Redirects cheat sheet; CWE-601; WSTG 4.11.4 | no |
| Session fixation (CWE-384): attacker sets a known session ID before login. Prevent: issue a new ID at authentication. Session hijacking = stealing a valid ID. | OWASP "Session fixation"; OWASP Session Management cheat sheet; CWE-384; MITRE T1539 | no |
| Parameter tampering, HTTP parameter pollution (duplicate names), cookie poisoning, hidden-field manipulation: server trusts client-supplied values. Prevent: server-side validation and authorization. | OWASP "Web Parameter Tampering"; WSTG 4.7.4 HPP; CWE-472 | no |
| Server-side template injection (CWE-1336): user input evaluated by a template engine; a math expression coming back computed is the classic indicator. Prevent: never build templates from input, logic-less or sandboxed templates. | WSTG 4.7.18; PortSwigger SSTI; CWE-1336 | no |
| Unrestricted file upload (CWE-434): a script uploaded and executed. Prevent: allowlist extensions, verify content, rename, store outside web root, no execute permission, size limits, malware scan. | OWASP File Upload cheat sheet; OWASP "Unrestricted File Upload"; CWE-434 | no |
| Web shell: a server-side script that lets an attacker run commands through HTTP; ATT&CK persistence T1505.003.
