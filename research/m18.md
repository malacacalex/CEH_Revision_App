# Research: M18 IoT and OT Hacking

Scope: the six sections in `content/modules/m18/meta.json`. The public CEH v13 course page lists the module's
key topics (IoT and OT concepts, IoT and OT attacks, hacking methodologies, tools and countermeasures). That
list is used for scope only; all wording below is ours, from public primary sources. The module is written
from a defender's angle, at the level the multiple-choice exam tests: what each architecture, protocol and
threat class is, how to recognize it (port, tool name, output line, log or traffic pattern), how to detect it
and the countermeasure. No attack walkthroughs, no exploit code.

Every fact was checked against at least two independent sources. **verify** marks EC-Council-specific lists or
labels and facts backed by a single source.

Checked on 2026-09-24. URLs tested with curl and a browser User-Agent. Notes on sources:
- **MITRE ATT&CK for ICS renumbered several techniques in 2026** (for example Unauthorized Command Message is now
  a sub-technique of T1692 Unauthorized Message, Default Credentials is T1694.001 under Insecure Credentials,
  System/Module Firmware are T1693.001/.002 under Modify Firmware). Items therefore **name** techniques and never
  ask for an ID; the URLs cited are the current pages (titles checked on 2026-09-24).
- The OWASP IoT Top 10 2018 PDF is served from `wiki.owasp.org`; the `owasp.org/www-pdf-archive/...` copy and the
  `www-project-internet-of-things-top-10` page return 404. The project page `www-project-internet-of-things` and
  the ISTG / ISVS / IoTGoat project pages answer 200.
- wiki.wireshark.org protocol pages for DNP3, CoAP, MQTT, Modbus, ZigBee, OPC-UA return 404 (wiki migration);
  the Wireshark **display filter reference** pages (`/docs/dfref/...`) are cited instead.
- NIST glossary slugs that do not exist (404): purdue_model, historian, engineering_workstation, zigbee,
  software_defined_radio, fault_injection_attack, network_segmentation.
- modbus.org old `/docs/...pdf` paths return 404; the specification page and the `/file/secure/...` PDFs answer
  200. kali.org has no page for killerbee or rtl-sdr (404): the project GitHub / osmocom pages are cited.
- The FCC Cyber Trust Mark page and search.censys.io answer 403 (bot protection) and are not cited.
- CISA pages used for incidents: Mirai alert (2016), Stuxnet advisories ICSA-10-201-01C, ICSA-10-238-01B and
  ICSA-10-272-01, the 2015 Ukraine alert IR-ALERT-H-16-056-01, the CrashOverride alert (2017), the HatMan
  (Triton) malware analysis report MAR-17-352-01 and advisory AA22-083A (Triton section).

## IoT Concepts and Attacks

| Fact | Sources | verify |
|---|---|---|
| An IoT device has at least one transducer (sensor or actuator) and at least one network interface; it is often constrained (CPU, memory, power), long-lived and rarely updated, which limits on-device security. | NIST glossary "IoT device"; NISTIR 8228 | no |
| RFC 7452 describes four IoT communication patterns: device-to-device, device-to-cloud, device-to-gateway, back-end data sharing. | RFC 7452; RFC 8576 (IoT security state of the art) | no |
| EC-Council's IoT architecture layers: edge technology, access gateway, internet, middleware, application. | EC-Council course page (topic names only); RFC 7452 (gateway pattern) | **yes** (EC framing, `ec-council-specific`) |
| MQTT is a publish/subscribe protocol through a broker; QoS 0/1/2; topic wildcards `+` (one level) and `#` (multi-level); IANA ports 1883 (mqtt) and 8883 (secure-mqtt). | OASIS MQTT 5.0 and 3.1.1 specs; IANA registry | no |
| Mosquitto 2.x: `allow_anonymous` defaults to false unless no listeners are configured; ACLs restrict topics per user. Nmap `mqtt-subscribe` connects and prints topics such as `$SYS/...` with their last payloads. | mosquitto.conf(5); Mosquitto authentication methods; Nmap NSE mqtt-subscribe | no |
| CoAP (RFC 7252) is a REST-style protocol over UDP for constrained nodes: port 5683, `coaps` over DTLS on 5684; resource discovery at `/.well-known/core`; RFC 7252 §11.3 warns about amplification. Nmap `coap-resources` lists resources. | RFC 7252; IANA registry; Nmap NSE coap-resources | no |
| Zigbee is built on IEEE 802.15.4 (low-power mesh); 6LoWPAN carries IPv6 over 802.15.4 (RFC 4944); Matter is an IP-based smart-home standard (Wi-Fi/Thread) that uses BLE for commissioning; LoRaWAN is an LPWAN with gateways; Z-Wave is a sub-GHz home mesh. | CSA Zigbee and Matter pages; IEEE 802.15.4; RFC 4944; LoRa Alliance; Z-Wave Alliance | no |
| Bluetooth: BLE pairing "Just Works" provides no MITM protection; Numeric Comparison / Passkey / OOB do. | NIST SP 800-121r2 upd1; Bluetooth core spec overview | no |
| OWASP IoT Top 10 2018: I1 Weak, Guessable, or Hardcoded Passwords; I2 Insecure Network Services; I3 Insecure Ecosystem Interfaces; I4 Lack of Secure Update Mechanism; I5 Use of Insecure or Outdated Components; I6 Insufficient Privacy Protection; I7 Insecure Data Transfer and Storage; I8 Lack of Device Management; I9 Insecure Default Settings; I10 Lack of Physical Hardening. | OWASP IoT Top 10 2018 PDF; OWASP IoT project page; OWASP IoT Top 10 2018 mapping (GitHub) | no |
| Mirai (2016): scanned for Telnet on 23/TCP and 2323/TCP and logged in with a list of 62 default username/password pairs; >380,000 devices claimed; 620 Gbps attack on KrebsOnSecurity; lives in memory so a reboot clears it, but a device with the default password is reinfected quickly; source code published. | CISA alert "Heightened DDoS threat posed by Mirai and other botnets"; USENIX Security 2017 "Understanding the Mirai Botnet"; Cloudflare Mirai glossary | no |
| Radio and physical attack classes: jamming (DoS on the channel), replay (re-sending captured valid messages), Sybil (one node claims many identities), side-channel (leakage through power/timing/EM). | NIST glossary: jamming, replay attack, Sybil attack, side-channel attack | no |
| EC-Council also names the rolling-code (jam-and-replay) attack, BlueBorne, fault injection and "exploit kits" among IoT attacks. | EC-Council course page (scope); NIST glossary replay attack | **yes** (EC framing) |
| An IoT botnet is used for DDoS (ATT&CK Network Denial of Service); default accounts map to ATT&CK Valid Accounts: Default Accounts. | MITRE T1498; MITRE T1078.001; CISA Mirai alert | no |

## OT Concepts and Attacks

| Fact | Sources | verify |
|---|---|---|
| OT = programmable systems that interact with the physical environment; ICS covers SCADA (geographically dispersed, e.g. pipelines, grids), DCS (process control within a plant), PLCs; also HMI, RTU, IED, data historian, SIS. | NIST SP 800-82r3; NIST glossary (OT, ICS, SCADA, DCS, PLC, HMI, RTU, IED, SIS, data historian) | no |
| OT priorities differ from IT: safety and availability first; patching, rebooting and active scanning are constrained; long lifetimes; many field devices and protocols cannot authenticate (replay, modification, spoofing possible at Level 0). | NIST SP 800-82r3 (§5.3.6 and IT/OT comparison); CISA ICS topic page | no |
| Purdue model: Level 0 field devices (sensors, actuators), Level 1 local controllers (PLC, RTU), Level 2 local supervisory (HMI, alarm servers), Level 3 site operations (historian, engineering workstations, site HMIs), Level 4 business network, Level 5 enterprise; an industrial DMZ ("Level 3.5") is added in practice; Level 4 must not talk directly to Levels 0-2. | SANS "Introduction to ICS security part 2"; NIST SP 800-82r3 (Fig. 16 and firewall rules) | no |
| An SIS brings the process to a safe state when limits are exceeded; it should be independent of the basic process control system. | NIST SP 800-82r3; NIST glossary SIS | no |
| OT protocol ports (IANA): Modbus/TCP 502 (mbap), DNP3 20000, Siemens S7comm over ISO-TSAP 102, BACnet/IP 47808/udp, EtherNet/IP 44818 (explicit) and 2222 (I/O), IEC 60870-5-104 2404, OPC UA 4840, HART-IP 5094, PROFINET RT 34962; Niagara Fox 1911 and OMRON FINS 9600 are per Nmap. | IANA registry; Nmap NSE pages (fox-info, omron-info, s7-info, enip-info, bacnet-info) | no |
| Classic Modbus has no authentication or encryption; any client that can reach a server can read or write registers and coils. Modbus/TCP Security (TLS) exists on 802/tcp but is rarely deployed. | Modbus application protocol spec + messaging guide; NIST SP 800-82r3 | no (802 port: IANA "mbap-s") |
| DNP3 (IEEE 1815) is used in electric and water utilities between masters and outstations; Secure Authentication (SAv5/SAv6) adds challenge-response. | DNP Users Group overview; IEEE 1815 page | no |
| ATT&CK for ICS impact techniques: Loss of View, Denial of View, Manipulation of View, Loss of Control, Denial of Control, Manipulation of Control, Loss of Safety, Damage to Property, Loss of Availability. | MITRE ATT&CK ICS technique pages; ATT&CK ICS matrix | no |
| Other ATT&CK for ICS techniques used here: Internet Accessible Device, Default Credentials, Remote Services, External Remote Services, Exploitation of Remote Services, Replication Through Removable Media, Adversary-in-the-Middle, Program Download, Program Upload, Modify Parameter, Change Operating Mode, Modify Firmware, Unauthorized Command Message, Brute Force I/O, Point & Tag Identification, Remote System Information Discovery. | MITRE ATT&CK ICS technique pages (titles checked 2026-09-24) | no |
| Stuxnet (found 2010): Windows worm spread by USB and network shares, used several zero-days (LNK, print spooler), targeted Siemens STEP 7 / WinCC and S7-315/S7-417 PLCs driving frequency converters, changed motor speeds while showing operators normal values, hid PLC changes with a rootkit. | CISA ICSA-10-201-01C, ICSA-10-238-01B, ICSA-10-272-01; MITRE S0603; Symantec Stuxnet dossier; NIST SP 800-82r3 | no |
| 2015 Ukraine grid attack: spear-phishing with BlackEnergy, remote control of SCADA/HMIs to open breakers, ~225,000 customers out, KillDisk wiper, serial-to-Ethernet firmware overwritten, UPS scheduled outages. | CISA IR-ALERT-H-16-056-01; MITRE C0028 | no |
| Industroyer / CrashOverride (Dec 2016, Kyiv substation): modular malware speaking IEC 60870-5-101, IEC 60870-5-104, IEC 61850 and OPC DA; abuses legitimate protocol functions; wiper; possible Siemens SIPROTEC relay DoS. Industroyer2 (2022) used IEC-104. | CISA CrashOverride alert; MITRE S0604, C0025, S1072 | no |
| Triton / TRISIS / HatMan (2017, Saudi petrochemical plant): targeted Schneider Electric Triconex safety controllers over the TriStation protocol; a mismatch between redundant processors tripped the SIS to a safe shutdown, which exposed it; the controller's key switch should stay in RUN. | CISA MAR-17-352-01 (HatMan) and AA22-083A; MITRE S1009, C0030; NIST SP 800-82r3 | no |
| Later OT cases: INCONTROLLER/PIPEDREAM (2022 toolset against Schneider/OMRON PLCs and OPC UA), FrostyGoop (2024, Modbus TCP), Unitronics PLC defacements with default passwords (2023). | CISA AA22-103A; MITRE S1045, S1165; CISA AA23-335A | no |
| EC-Council OT attack labels: HMI-based attacks, side-channel attacks, hacking PLCs, hacking industrial systems through RF remote controllers (replay, command injection, e-stop abuse, malicious reprogramming), OT malware. | EC-Council course page (scope); MITRE ICS techniques | **yes** (EC framing) |

## OT Hacking Methodology

| Fact | Sources | verify |
|---|---|---|
| EC-Council's OT hacking phases: information gathering, vulnerability scanning, launch attacks, gain remote access, maintain access (same five as IoT). | EC-Council course page (scope) | **yes** (EC framing) |
| Exposure discovery: Shodan/Censys find internet-reachable HMIs and PLCs (ATT&CK ICS Internet Accessible Device); CISA says OT devices "are quickly found" by searching open ports on public IP ranges. | Shodan help; MITRE T0883; CISA primary mitigations for OT | no |
| Active scanning can crash fragile OT devices; SP 800-82r3 recommends passive monitoring and careful, coordinated active scanning in test or maintenance windows. | NIST SP 800-82r3; CISA OT asset inventory guidance | no |

| Discovery techniques as ATT&CK ICS names: Remote System Discovery, Remote System Information Discovery, Network Sniffing, Point & Tag Identification, Program Upload (reading the logic from a controller). | MITRE ATT&CK ICS technique pages | no |
| Defender tools that recognize OT traffic: GRASSMARLIN (NSA, passive OT network mapping), CISA ICSNPP (Zeek parsers for ICS protocols), CISA Malcolm (network traffic analysis suite), CISA CSET (self-assessment tool). | GitHub nsacyber/GRASSMARLIN; GitHub cisagov/ICSNPP, Malcolm, cset; CISA CSET page | no |
| Default credentials on internet-facing PLCs and HMIs (for example Unitronics, 2023) and remote access tools (Oldsmar water plant, 2021) are recurring entry points. | CISA AA23-335A; CISA AA21-042A; MITRE Default Credentials, External Remote Services | no |

## OT Attack Countermeasures

| Fact | Sources | verify |
|---|---|---|
| NIST SP 800-82r3 (Sept 2023) "Guide to Operational Technology (OT) Security": defense-in-depth architecture, segmentation with DMZs, separate IT/OT credentials, unidirectional gateways, OT overlay of SP 800-53 controls. | SP 800-82r3 page + PDF | no |
| ISA/IEC 62443: zones (assets grouped by risk / shared security requirements) and conduits (the communication paths between zones); SL-T target and SL-A achieved security levels (SL 1-4); seven foundational requirements FR1-FR7 (identification and authentication control, use control, system integrity, data confidentiality, restricted data flow, timely response to events, resource availability); parts 2-1 (asset owner programme), 3-3 (system requirements), 4-1 (secure product development), 4-2 (component requirements). | IEC SyC-SE page on IEC 62443; ISA 62443 series page; ISAGCA "How to define zones and conduits" | no |
| Unidirectional gateway / data diode: hardware that allows data to flow in one direction only (e.g. historian replication out of OT). | NIST glossary unidirectional gateway, data diode; NIST SP 800-82r3 | no |
| CISA primary OT mitigations: remove OT connections from the public internet, change default passwords, secure remote access (private network, VPN with phishing-resistant MFA), segment IT and OT, be able to operate manually. | CISA primary mitigations for OT; CISA CPGs; CISA AA22-083A actions | no |
| ATT&CK for ICS mitigations: Network Segmentation, Filter Network Traffic, Network Allowlists, Communication Authenticity, Software Process and Device Authentication, Code Signing, Out-of-Band Communications Channel, Data Backup, Audit, Update Software, Password Policies, Multi-factor Authentication. | MITRE ATT&CK ICS mitigation pages | no |
| Stuxnet lessons: control removable media, allowlist applications on engineering workstations, verify PLC logic against a known-good copy, do not trust the HMI view alone. Triton lessons: keep the SIS on its own network, keep the controller key switch in RUN, alarm on program changes. | CISA ICSA-10-238-01B; CISA MAR-17-352-01; MITRE Code Signing / Audit mitigations | no |
| Asset inventory is the foundation: CISA's OT asset inventory guidance lists the attributes to record; passive monitoring builds it safely. | CISA OT asset inventory guidance; NIST SP 800-82r3 | no |
