# Research: M19 Cloud Computing

Scope: the eight sections in `content/modules/m19/meta.json`. The public CEH v13 course page lists the module's
key topics (cloud computing, fog and edge computing, containers, Docker, Kubernetes, serverless, OWASP cloud
risks, cloud threats and attacks, cloud hacking methodology, AWS, Azure and Google Cloud hacking, container
hacking, cloud network security, cloud security controls and tools) and its labs (S3 bucket enumeration, IAM
privilege escalation through a misconfigured policy, Docker image vulnerability assessment). That list is used
for scope only; all wording is ours, from public primary sources.

Angle: exam knowledge with a defender's view. Threats are described at recognition level (what it is, how to
spot it, what stops it); no step-by-step attack procedures.

Every fact was checked against at least two independent sources where possible. **verify** marks
EC-Council-specific names and framing, and facts backed by a single source.

Checked on 2026-09-24. All cited URLs tested with curl and a browser User-Agent (list in the scratch folder,
`m19/urls_used.txt`). Removed as 404: NIST glossary "multi_tenancy", "serverless", "serverless_computing",
"function_as_a_service", "fog_computing", "edge_computing", "cryptojacking", "vm_escape"; csrc.nist.gov
landing page for SP 500-292 (replaced by the nist.gov publication page and the tsapps PDF); two CISA pages on the
Kubernetes hardening guide and the APT10 alert (replaced by MITRE G0045 and T1199); the old OWASP Cloud Top 10
PDF. Dropped: media.defense.gov and pwc.co.uk PDFs (403 from bot protection, not needed). The Kubernetes "4C"
model was removed from the current security overview page, so it is cited from a Wayback snapshot (2023-01-27).

## Cloud Computing Concepts

| Fact | Sources | verify |
|---|---|---|
| NIST: 5 essential characteristics (on-demand self-service, broad network access, resource pooling, rapid elasticity, measured service), 3 service models (SaaS, PaaS, IaaS), 4 deployment models (private, community, public, hybrid). | NIST SP 800-145 (landing page and PDF); NIST glossary "cloud computing", "resource pooling", "measured service" | no |
| Community cloud = exclusive use by a community with shared concerns; hybrid = two or more distinct infrastructures bound for data and application portability (cloud bursting). | NIST SP 800-145; NIST glossary "community cloud", "hybrid cloud" | no |
| Multi-cloud (several public providers side by side) is named by EC-Council; it is not a NIST deployment model. | EC-Council course page; CSA Security Guidance | **yes** |
| Five cloud actors: consumer, provider, auditor, broker, carrier. Auditor = independent assessment; carrier = connectivity and transport; broker = manages use, performance and delivery and negotiates relationships. | NIST SP 500-292 (nist.gov page and PDF); NIST glossary "cloud broker", "cloud auditor", "cloud carrier" | no |
| Broker service categories: intermediation (enhance one service), aggregation (combine services, fixed providers), arbitrage (combine, providers chosen dynamically). | NIST SP 500-292 §2.5 and glossary entries 22-23 (PDF); NIST glossary "cloud broker" | no (single document, but it is the defining source) |
| Shared responsibility: AWS "security of the cloud" vs "security in the cloud"; Microsoft matrix with data, devices, accounts and identities always the customer's; Google adds "shared fate". | AWS shared responsibility model; Microsoft Learn "Shared responsibility in the cloud"; Google Cloud "Shared responsibilities and shared fate" | no |
| Serverless/FaaS: provider manages servers, OS, runtime and scaling; customer owns code, dependencies, function permissions and input validation. | AWS Lambda "What is Lambda" and "Security in Lambda"; Azure Functions security concepts; OWASP Serverless Top 10 | no |
| Containers share the host kernel; VMs get hardware-level isolation from a hypervisor. | NIST SP 800-190 §2-3; NIST glossary "container", "hypervisor" | no |
| Fog computing = layered model with fog nodes between end devices and the central cloud, latency-aware; edge = the layer of the end devices; mist = lightweight fog at the edge. | NIST SP 500-325 (landing page and PDF, Annex A) | no (defining document) |

| Fact | Sources | verify |
|---|---|---|
| CSA Top Threats 2024 (11 items): misconfiguration and inadequate change control; IAM; insecure interfaces and APIs; inadequate cloud security strategy; insecure third-party resources; insecure software development; accidental cloud disclosure; system vulnerabilities; limited visibility; unauthenticated resource sharing; APTs. | CSA "Top Threats to Cloud Computing 2024" artifact page; CSA Top Threats working group page | no |

| Side-channel attacks exploit shared hardware (multi-tenancy); mitigations are provider patching and single-tenant hosts. | NIST glossary "side channel attack"; NIST SP 800-125; NIST SP 800-144 | no |
| Cloud hopping: compromise of managed service providers to reach their clients (menuPass / APT10). | MITRE ATT&CK G0045 and T1199; EC-Council course page (term) | **yes** (EC-Council label) |

| Wrapping attack: XML signature wrapping in SOAP messages. | EC-Council course page only (no stable public primary source found) | **yes** |
