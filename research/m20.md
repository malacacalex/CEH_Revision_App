## Cryptography Concepts and Encryption Algorithms

| Fact | Sources | verify |
|---|---|---|
| Cryptography services: confidentiality (encryption), integrity (hashes, MACs), authentication and non-repudiation (digital signatures). | NIST SP 800-175B Rev. 1; NIST glossary "non-repudiation", "digital signature" | no |
| Symmetric cryptography uses one shared secret key for both operations; n parties need n(n−1)/2 pairwise keys (the key distribution problem). | NIST glossary "symmetric cryptography"; Handbook of Applied Cryptography (HAC) ch. 1 | no |
| Asymmetric (public key) cryptography uses a key pair: the public key encrypts or verifies, the private key decrypts or signs. Slower than symmetric, so systems use hybrid encryption (public key protects a random session key). | NIST glossary "asymmetric cryptography", "public key cryptography"; RFC 9580 (OpenPGP) and RFC 8551 (S/MIME) describe the hybrid model | no |
| Block cipher works on fixed-size blocks; stream cipher combines a keystream with the data bit by bit or byte by byte. | NIST glossary "block cipher", "stream cipher"; HAC ch. 1 | no |
| AES (Rijndael): 128-bit block, 128/192/256-bit keys, 10/12/14 rounds. | FIPS 197; NIST block cipher techniques project | no |
| DES: 64-bit block, 56-bit effective key; FIPS 46-3 withdrawn in 2005. | FIPS 46-3 page; NIST news on SP 800-67 withdrawal | no |
| 3DES (TDEA): three DES operations, 64-bit block. 2TDEA disallowed in the 2017 revision; applying protection with TDEA disallowed after 31 Dec 2023; SP 800-67 Rev. 2 withdrawn 1 Jan 2024; decryption of legacy data still allowed. | NIST news "NIST to withdraw SP 800-67 Rev. 2"; SP 800-131A Rev. 2 | no |
| Double encryption only gives about k+1 bits of strength against a meet-in-the-middle attack, which is why "2DES" was never used and TDEA uses three operations. | HAC ch. 7 (Fact 7.33); NIST SP 800-67 Rev. 2 | no |
| Blowfish: 64-bit block, 32–448-bit key. Twofish: 128-bit block, keys up to 256 bits, AES finalist. Both are in the OpenPGP algorithm list. | schneier.com Blowfish and Twofish pages; RFC 4880 §9.2 | no |
| RC4 is a stream cipher; RFC 7465 prohibits RC4 cipher suites in TLS. ChaCha20 is a stream cipher with a 256-bit key; ChaCha20-Poly1305 is an AEAD used in TLS 1.3. | RFC 7465; RFC 8439; RFC 8446 | no |
| Modes: ECB encrypts equal blocks to equal ciphertext (leaks patterns); CBC chains blocks with an IV; CTR turns a block cipher into a stream; GCM is authenticated encryption and needs a unique IV per key. SP 800-131A Rev. 3 (draft) proposes retiring ECB for confidentiality. | SP 800-38A; SP 800-38D; SP 800-131A Rev. 3 ipd | no |
| RSA security rests on factoring; FIPS 186-5 signatures need a modulus ≥ 2048 bits. | RFC 8017; FIPS 186-5 | no |
| Diffie-Hellman is key agreement (both sides derive the same secret), based on discrete logarithms; it does not authenticate the peers by itself. | RFC 2631; NIST SP 800-56A Rev. 3; NIST glossary "key agreement" | no |
| ECC gives the same strength with much smaller keys: 256-bit ECC ≈ 3072-bit RSA ≈ 128-bit security. Equivalences: 112 = 3TDEA/RSA 2048/ECC 224; 128 = AES-128/RSA 3072/ECC 256; 192 = AES-192/RSA 7680/ECC 384; 256 = AES-256/RSA 15360/ECC 512. | SP 800-57 Part 1 Rev. 5 (Table 2); SP 800-131A Rev. 2 | no |
| FIPS 186-5 (2023) no longer approves DSA for signature generation (verify only), keeps RSA and ECDSA, adds EdDSA. | FIPS 186-5 (Appendix E); SP 800-131A Rev. 3 ipd | no |
| Hash: fixed-size digest, one-way. Properties: preimage, second-preimage and collision resistance. | NIST glossary "hash function", "collision resistance", "preimage resistance"; SP 800-107 Rev. 1 | no |
| Digest sizes: MD5 128, SHA-1 160, SHA-2 family 224/256/384/512 (FIPS 180-4), SHA-3 224–512 plus SHAKE XOFs (FIPS 202). | FIPS 180-4; FIPS 202; RFC 6151 (MD5); RFC 6194 (SHA-1) | no |
| MD5 is not collision resistant (RFC 6151); a practical SHA-1 collision was published in 2017 (SHAttered); NIST will retire SHA-1 by 31 Dec 2030. | RFC 6151; shattered.io; NIST news "NIST retires SHA-1" | no |
| HMAC = keyed hash (FIPS 198-1, RFC 2104): integrity and data origin authentication with a shared key, but no non-repudiation. | FIPS 198-1; RFC 2104; NIST glossary "message authentication code" | no |
| Digital signature: hash the message, sign the digest with the private key, verify with the public key; gives integrity, authentication, non-repudiation. | FIPS 186-5; NIST glossary "digital signature" | no |
| One-time pad: key truly random, as long as the message, never reused → unconditionally secure. Kerckhoffs: security must rest on the key, not on the secrecy of the algorithm. | NIST glossary "one-time pad"; HAC ch. 1 | no |
| Classical ciphers: substitution (replace symbols, e.g. Caesar) and transposition (reorder symbols). | HAC ch. 1; CrypTool | no |
| Shor's algorithm would break RSA, DH and ECC on a large quantum computer; Grover's algorithm speeds key search, so larger symmetric keys (AES-256) and hashes are advised. | NIST IR 8105; CISA quantum page | no |
| Post-quantum standards (Aug 2024): FIPS 203 ML-KEM (from CRYSTALS-Kyber, key encapsulation), FIPS 204 ML-DSA (Dilithium, signatures), FIPS 205 SLH-DSA (SPHINCS+, hash-based signatures, backup). HQC selected in March 2025 as a backup KEM. | NIST news Aug 2024; FIPS 203/204/205 pages; NIST news March 2025 | no |
| QKD uses quantum physics to agree a key but does not authenticate the peers, so it still needs classical authentication; NCSC and ANSSI prefer post-quantum cryptography. | NCSC "Quantum security technologies"; ANSSI QKD position paper | no |
| Lightweight cryptography: NIST selected Ascon (SP 800-232, AEAD and hashing) for constrained devices. | SP 800-232; NIST lightweight cryptography project | no |
| Government Access to Keys (GAK) is EC-Council's term for key escrow to authorities. | NIST glossary "key escrow"; EC-Council course page (scope) | yes (EC term) |

## Applications of Cryptography

| Fact | Sources | verify |
|---|---|---|
| PKI components: certification authority (issues and signs), registration authority (verifies identity), certificates, repositories, revocation (CRL, OCSP), end entities. | SP 800-32; RFC 5280; NIST glossary "registration authority" | no |
| X.509 v3 certificate fields: version, serial number, signature algorithm, issuer, validity, subject, subject public key info, extensions (subjectAltName, keyUsage, basicConstraints). Never contains the private key. | RFC 5280 §4.1; OpenSSL x509 docs | no |
| Chain of trust: leaf → intermediate CA → root CA. A root is self-signed and acts as the trust anchor. | RFC 5280; NIST glossary "trust anchor", "root certificate authority" | no |
| Self-signed certificate: issuer = subject, not trusted by browsers by default; `openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 365` makes one. | NIST glossary "self-signed certificate"; openssl-req docs | no |
| A CSR is a PKCS #10 request containing the public key and subject, signed with the private key. | RFC 2986; openssl-req docs | no |
| Revocation: CRL = signed list published periodically; OCSP = real-time status query for one certificate. | RFC 5280; RFC 6960; NIST glossary "certificate revocation list" | no |
| Certificate Transparency: public append-only logs of issued certificates so misissuance can be detected. | RFC 6962; RFC 9162; certificate.transparency.dev | no |
| ACME automates domain-validated certificates (Let's Encrypt, certbot). | RFC 8555; Let's Encrypt "How it works" | no |
| TLS 1.3: 1-RTT handshake; key exchange only (EC)DHE or PSK, so forward secrecy by default; static RSA and DH key transport removed; only AEAD ciphers; everything after ServerHello encrypted, including the certificate; optional 0-RTT data can be replayed. | RFC 8446; OWASP TLS cheat sheet | no |
| SSL 3.0 deprecated (RFC 7568); TLS 1.0 and 1.1 deprecated (RFC 8996); SP 800-52 Rev. 2 requires TLS 1.2 and TLS 1.3 support. | RFC 7568; RFC 8996; SP 800-52 Rev. 2 | no |
| HSTS tells browsers to use HTTPS only for a host, blocking SSL stripping. | RFC 6797; OWASP HSTS cheat sheet | no |
| S/MIME: X.509 certificates issued by CAs (hierarchical trust), CMS format. PGP/OpenPGP: user-managed keys and web of trust; GnuPG implements it. Both are hybrid: random session key for the message, recipient public key for the session key; signatures with the sender private key. | RFC 8551; RFC 5652; RFC 9580; RFC 4880; GnuPG manual | no |
| Full-disk encryption protects data at rest on a powered-off or lost device, not a running unlocked one. | SP 800-111; NIST glossary "full disk encryption"; BitLocker countermeasures | no |
| BitLocker (Windows) uses the TPM and XTS-AES, `manage-bde -status` shows state; FileVault (macOS); LUKS with cryptsetup (Linux); VeraCrypt supports hidden volumes for plausible deniability. | Microsoft BitLocker docs; manage-bde docs; Apple Platform Security; cryptsetup man page; VeraCrypt docs | no |
| Hash tools: `sha256sum`, PowerShell `Get-FileHash` (SHA256 default), `certutil -hashfile`, `openssl dgst -sha256`, NirSoft HashMyFiles. | GNU coreutils; Microsoft docs; openssl-dgst docs; NirSoft | no |
| File and message encryption tools: `openssl enc`, `gpg -c` (symmetric), AxCrypt, CrypTool (education). | OpenSSL enc docs; GnuPG manual; axcrypt.net; cryptool.org | no |
| Blockchain: hash-linked blocks in a distributed, tamper-evident ledger; consensus by proof of work or proof of stake; smart contracts are code stored on chain. | NIST IR 8202; bitcoin.pdf; NIST glossary "blockchain", "smart contract" | no |
| EC-Council's v13 lab "Perform Cryptography using AI": using an AI assistant to produce and explain encryption or hashing commands. | EC-Council course page; OWASP Top 10 for LLM (general AI limits) | yes (EC framing) |

## Cryptanalysis Methods and Cryptography Attacks

| Fact | Sources | verify |
|---|---|---|
| Attack models by attacker knowledge: ciphertext-only, known-plaintext, chosen-plaintext, adaptive chosen-plaintext, chosen-ciphertext. | HAC ch. 1 §1.13; NIST glossary "chosen plaintext attack", "chosen ciphertext attack" | no |
| Linear cryptanalysis (known plaintext, linear approximations) and differential cryptanalysis (chosen plaintext, input/output differences) are the classic block cipher methods; EC-Council also lists integral cryptanalysis. | HAC ch. 7; NIST glossary "cryptanalysis" | yes (integral is EC-specific) |
| Brute force tries every key; each added key bit doubles the work (2^n keys). | HAC ch. 1; SP 800-57 Part 1 | no |
| Birthday attack: collisions in an n-bit hash appear after about 2^(n/2) tries; Sweet32 applies the same bound to 64-bit block ciphers (3DES, Blowfish) in long sessions. | SP 800-107 Rev. 1; sweet32.info; NIST 3DES withdrawal news | no |
| Rainbow tables are precomputed hash chains for unsalted hashes; a unique salt per password defeats them. | OWASP Password Storage Cheat Sheet; NIST SP 800-63B-4 | no |
| Dictionary and brute-force/mask cracking with hashcat (`-a 0` straight, `-a 3` brute force, `-m 0` MD5, `-m 1000` NTLM, `-m 3200` bcrypt) and John the Ripper. | hashcat wiki; hashcat example hashes; John the Ripper docs; MITRE T1110.002 | no |
| Side-channel attacks learn secrets from timing, power, electromagnetic or acoustic leakage, not from the math. | NIST glossary "side channel attack", "differential power analysis"; Kocher timing paper | no |
| Cold boot and DMA attacks read keys from memory of a running or sleeping machine; BitLocker guidance adds pre-boot PIN and DMA protection. | Microsoft BitLocker countermeasures; SP 800-111 | no |
| Rubber-hose cryptanalysis: getting the key by coercion or bribery of a person. | EC-Council course page (scope); HAC ch. 1 (non-technical attacks mention) | yes (EC term) |
| Padding oracle: an error that reveals whether padding was valid lets an attacker decrypt CBC data; POODLE exploited it in SSL 3.0. | CISA POODLE alert; Möller et al. POODLE paper; RFC 7568 | no |
| Downgrade attacks push a connection to weak crypto: FREAK and Logjam (export-grade RSA/DH), DROWN (SSLv2). TLS 1.3 adds a downgrade sentinel in ServerHello.random. | weakdh.org; drownattack.com; RFC 7457; RFC 8446 §4.1.3 | no |
| Heartbleed (CVE-2014-0160): OpenSSL heartbeat over-read leaks memory, including private keys; Nmap script ssl-heartbleed detects it. | CISA alert; heartbleed.com; Nmap NSE doc | no |
| ROBOT: Bleichenbacher-style oracle on RSA PKCS #1 v1.5 key exchange. DUHK: hard-coded seed key in ANSI X9.31 RNG lets traffic be decrypted. | robotattack.org; duhkattack.com; RFC 8446 (removes RSA key transport) | no |
| Man-in-the-middle on unauthenticated Diffie-Hellman; replay attacks re-send captured valid messages. | NIST glossary "man-in-the-middle attack", "replay attack"; MITRE T1557 | no |
| Blockchain attacks: 51 % (majority) attack lets the attacker rewrite recent blocks and double-spend; smart contract reentrancy (SWC-107) re-enters a function before state is updated. | Ethereum PoW and PoS attack docs; bitcoin.pdf; SWC-107; OWASP Smart Contract Top 10 | no |
| Sybil and eclipse attacks (many fake identities; isolating a node's peers) appear in EC-Council's blockchain attack list. | Ethereum PoS attack-and-defense doc; EC-Council course page | yes (EC list) |
| "Harvest now, decrypt later": record encrypted traffic today, decrypt when a quantum computer exists. | CISA quantum page; NCSC PQC migration timelines | no |
| Attacker techniques around crypto: T1110.002 password cracking, T1552.004 stolen private keys, T1649 steal or forge certificates, T1553.004 install root certificate, T1600 weaken encryption, T1558.003 Kerberoasting. | MITRE ATT&CK pages | no |
| Cryptanalysis tools: CrypTool (learning), RsaCtfTool (weak RSA keys), hashcat, John; TLS audit with testssl.sh, sslscan, Nmap ssl-enum-ciphers (grades A–F). | cryptool.org; RsaCtfTool GitHub; testssl.sh; sslscan GitHub; Nmap NSE doc | no |

## Cryptography Attack Countermeasures

| Fact | Sources | verify |
|---|---|---|
| Use approved algorithms and sizes: AES, SHA-2/SHA-3, RSA ≥ 2048 (3072 for 128-bit strength), ECC ≥ P-256; retire DES, 3DES, RC4, MD5 and SHA-1. | SP 800-131A Rev. 2; SP 800-57 Part 1 Rev. 5; RFC 7465 | no |
| Key management: cryptoperiods, one key per purpose, rotation, secure storage (HSM, TPM), never hard-code keys. | SP 800-57 Part 1 Rev. 5; OWASP Key Management cheat sheet; OWASP Top 10 Cryptographic Failures | no |
| Store passwords with a salted, slow, memory-hard hash: Argon2id, scrypt, bcrypt, or PBKDF2 (600,000 iterations for HMAC-SHA-256). | OWASP Password Storage cheat sheet; RFC 9106; SP 800-132; SP 800-63B-4 | no |
| TLS: 1.2 and 1.3 only, AEAD suites, (EC)DHE for forward secrecy, HSTS, valid certificates; test with testssl.sh, SSL Labs or Nmap. | SP 800-52 Rev. 2; OWASP TLS cheat sheet; RFC 8996 | no |
| Randomness: use a CSPRNG/DRBG; never reuse an IV or nonce with the same key (GCM breaks). | SP 800-90A Rev. 1; RFC 4086; SP 800-38D | no |
| Side-channel defenses: constant-time code, blinding, shielding; patch crypto libraries promptly (Heartbleed). | Kocher timing paper; CISA Heartbleed alert | no |
| Disk encryption: TPM + PIN, hibernate or shut down rather than sleep, DMA protection. | Microsoft BitLocker countermeasures; SP 800-111 | no |
| PQC migration: inventory cryptography, build crypto agility, plan hybrid key exchange; NIST draft IR 8547 deprecates 112-bit RSA/ECC after 2030 and disallows quantum-vulnerable public key algorithms after 2035; NCSC targets 2028/2031/2035 milestones. | NIST IR 8547 ipd (draft); NCSC PQC migration timelines; CISA quantum readiness factsheet | no (IR 8547 is a draft) |
| Smart contract defenses: checks-effects-interactions pattern, reentrancy guards, audits. | Ethereum smart contract security docs; SWC-107 | no |
